## 当前项目基线与派发约束

**首要验收标准为文案克制。默认不新增解释小字、副标题、状态罗列与重复数据。新增文案逐句检查，删掉后仍能完成当前操作就删除，拿不准先省略；每次委派完整带入全局规则的“第一优先级”一节。**

购买区仅保留当前拖放操作或失败原因，删除重复的“收入手牌”、价格和剩余格数说明。

更新于 2026-11-09。当前三合一项目的视觉基线与用户反馈在本节维护，后续历史继承条目按当前玩法与用户最新要求适用。

- 用户最新澄清采用**紫金主题的奇幻卡牌游戏 UI，搭配精致像素单位与特效**。按钮、面板和文字以原版细腻的色差、明暗层次、清晰字体与连续光效为依据；单位精灵与特效承担主要像素表达，局部既有像素边饰按原版使用。原版按钮样式及交互动效是项目基线，修复交互问题时保护这些表现。
- 每次交给 Claude 的任务都提供自包含提示，带入本节基线、适用的反向约束、目标对象、状态、视口、动效契约与验收条件。新建、续接和返工均适用，不能仅写“精致”“有质感”或“沿用之前风格”。
- 用户要求仅凭提示词试作时，仅提供文字要求。其他任务按授权附原版截图或源码依据。独立试作的形状、配色分配和动效参数须经项目采用后才成为设计依据。

### 按钮试作经验

2026-11-09 的纯提示词按钮试作被用户指出观感“脏”。以下问题转为后续派发与验收的明确约束。

| 观察到的问题 | 提示词中的反向约束 | 渲染检查 |
| --- | --- | --- |
| 紫色轮廓、浅色顶边与棕色底座叠加，转角出现零碎突出像素 | 禁止用多重描边、额外矩形套框、跨色系杂边和孤立亮点堆砌精致感；避免不连续的转角与厚度突变 | 在实际显示尺寸检查外轮廓连续性、转角节奏和边缘厚度，关注缩放后的碎边 |
| 五段硬切换的横向色带把按钮主体切碎 | 禁止机械堆叠等宽亮暗条带或无明确作用的色阶；每个色阶须服务主体面、高光或阴影 | 检查主体是否完整，是否出现搓板状横纹，邻接色阶是否过度抢眼 |
| 亮顶边、悬停白条和深色底座各自强调，缺少统一光照关系 | 禁止互相矛盾的受光方向，以及脱离形体的白条、亮边和阴影；禁止为每个状态另造一套材质 | 普通、悬停、按下状态共用一致的受光与厚度关系，按压反馈应有连续性 |
| “精致”“像素细节”等形容词未落实成可检查要求，且误将单位的像素表现套到所有 UI 控件 | 禁止以粗描边、任意颗粒、噪点或装饰叠层代替明确的形体设计；禁止强制所有按钮使用大像素台阶或擅自加入材质题材 | 对照原版与任务要求检查形状、色阶、信息层级及 UI 与角色的风格关系 |

### 用户认可的按钮参考

用户于 2026-11-09 提供并明确认可金色“开战”按钮，强调其光效与精致色差。参考图保存于 `source/output/ui-reference-20261109/approved-battle-button.png`。

- 主体为完整、清晰的长方形按钮面。上沿细亮金、主体浅金、下缘暖橙与底部深色分别表达受光、主体面和厚度，色差具有明确的形体作用。
- 深色中文与明亮按钮面形成清楚对比。柔和金色外发光使按钮从深色背景中突出，亮度与范围围绕主体控制。
- 本参考认可有功能的色差分区、边缘高光、阴影与柔光。前述反向约束针对无功能叠层、杂边、碎角和失去统一受光的处理，不能被解释为统一禁止渐变、金色亮边、色差分区或外发光。
- 静态参考可证明形状、配色与可见光效。按钮的扫光周期、按压幅度和时长从现有实现或用户明确要求取值，不能由静态图片推断。
- 独立试作提示中曾加入的强制像素台阶与禁止大面积平滑渐变要求已作废。“避免大面积光晕”也不得扩展为禁止原版的克制外发光。

### 每次派发附带的反向提示

以下文字随适用的按钮与控件任务传入执行者，再补充该次任务的具体对象和状态。

> 本项目采用紫金主题的奇幻卡牌游戏 UI，搭配精致像素单位与特效。按钮以原版及用户认可的金色按钮为基线，保留完整主体面、具有形体作用的精致色差、边缘高光、厚度阴影和克制柔光。禁止擅自重设计现有按钮，禁止强制像素台阶、粗颗粒、额外套框、多重杂色描边、碎角和孤立装饰亮点。禁止通过无功能的密集横向色带或噪点堆砌细节。禁止相互矛盾的光照、脱离形体的高光白条，以及状态之间的材质跳变。柔光允许在主体附近衰减；扫光需按原实现约束在按钮内，禁止形成突兀光块、遮挡文字或干扰相邻操作。每层颜色与光照均承担明确作用，在实际尺寸下保持清楚、协调。

- 独立新控件试作按用户授权决定形状，提示中仍明确风格、主题色及以上画质约束。未经用户采用的试作不能替换原版按钮。
- 动效要求逐项写明触发时机、作用范围、持续时间、幅度、重复触发与清理、reduced-motion 表现。现有按钮任务从原实现提取这些要求，禁止凭空加入循环扫光或新的材质动效。
- 验收查看真实尺寸的普通、悬停或聚焦、按下、禁用及动效中间帧。按钮还需放回完整游戏画面检查协调性、遮挡和操作可达性。交互检查与视觉检查分别记录结果。

## 1. 硬约束

- **手机横屏优先**
  - 不靠悬停；
  - 舞台字号 ≥ 18；
  - 点击区 ≥ 44px；
  - 出售用拖动（拖到底部出售区）。
- **性能**
  - 常驻补间只动 transform/opacity；精灵逐帧切图例外：在固定窗口内按素材帧率切换背景位置，不改布局、不另起 JS 计时循环；
  - 教学轮询只在状态变化时改 DOM；
  - 一次性特效 ≤ 600ms，2 倍速下减半；
  - 一次的粒子数 ≤ 24。
- **少字**
  - 词条只放标识，解释统一放「玩法说明 → 词条」页；
  - 补给传承通用规则只在图鉴规则页解释；单位详情只列自身记录数量、补给和实际出售预览，商店/图鉴静态卡不显示空记录；
  - 文案短、具体，不写抽象长句。
- **词条二选一**：能表意的做像素 icon，不能表意的用彩色「」短词，两种不并用。数值标签统一用像素牌。
- **正面数值**（格挡等）居中显示在单位脚下。

## 2. 单位与阶层 [复用]

- 立绘用 duelyst 单位帧图，按 defId 和奇兵列阵同名单位共用（`unitArt.ts` + `duelyst-units.css`）。
- idle 使用单一固定窗口，选中只换描边图、不重启时间轴；不额外叠加整身 bob。`idle-anchors.css` 仅抵消经过逐帧配准确认的8种整幅竖向位移，保留局部动作；新增素材不得按包围盒统一强行对齐。
- 阶层靠**单位光效和颜色**区分，不用外框圈：
  - 用由下往上的光点；不用旋转光环；
  - 各阶层要一眼分得清；
  - 除场上战斗单位外，凡是出现单位立绘的地方都加光效；
  - 阶层图标要有美术设计，不要生硬的徽章。
- 机制词条要有像炉石那样有质感的装饰特效，不用线框嘲讽框，也不用丑的黄盾：
  - 格挡：叠起来的半透明盾片；
  - 复生：脚下一圈淡金色光环；
  - 轮换：脚下一个循环箭头；
  - 溅射：身后有火星。
- 星级进度条放在单位头顶，要有清楚的边框。

## 3. 商店 [复用 SAP 经济代码]

- 货架 3 张起，不翻页（3→5 张逐步加）。
- 买卡时不播刷新特效。
- 总金币放左下；按钮上方不再标每张卡的价格。
- 广告刷新按钮写「广告刷新」，字要放得进框。
- 锁定或解锁卡时，关闭单位详情弹窗。
- 备战界面：
  - 我方单位大、在左；敌方预览小、在右；
  - 能升星受益的单位要高亮，样式和教学圈区分开。

## 4. 战斗表现 [简化]

- 布局：两列相对，横着排，队首在中线两侧。交锋就是两个队首对撞。
- 中线显示交锋数，大数字写当前次数（以前的 m/n 可以去掉）。
- 攻击和受击接帧图动画。普攻和施法要区分：施法 = 自定义光效 + 帧动作。
- 保留：
  - 追击用的残影（这里用在轮换的位移上）；
  - 目标指示线的发光；
  - 动态准星（不用斧头图标）。
- 因果要连线：凡是「A 让 B 怎么样」，都从 A 画到 B（飞镖手→敌方队首、医师→退后者、指挥官→队首）。
- 一个动词一种形状，颜色跟阵营。削弱用红色并往下掉，授予用图标落下。
- 触发标签写「单位名 · 能力」，比如「圣铸机兵 · 友军上前」，不写通用的「被动」。
- 飘字：
  - 不加框，要活泼不要死板；
  - 失败、金币不够用红叉，不用绿色。

## 5. 教学与图鉴 [复用，暂缓到核心可玩之后]

- 讲解词条时圈出触发它的单位或元素（包括结果框），镜头推近并平移过去：
  - 按画面自适应缩放，不要推得太近，画面要完整；
  - 不在屏幕中央弹气泡。
- 图鉴里的演示是用代码配置的实时小战斗，和正式战斗共用数据：
  - 底部常驻说明文字；
  - 关键时刻慢放、暂停、框出单位，配一个小气泡（如「上前时」），然后继续。
- 图鉴：
  - 复用游戏内的卡面；
  - 战斗内和主菜单两个入口统一；
  - 传说卡的玻璃效果不被裁掉；
  - 阶层标不重复显示。
- 卡面上的词条排版不能歪；有空间就把卡面放大。
- 跳过教学的按钮做小，放左上角，离操作热区远。

## 6. 产品体验 [复用]

- 教学结束后、第一局结束后各弹一次反馈。
- 反馈按钮显示 QQ 群（群号待定，占位写 `QQ_GROUP_TBD`）。
- 设置里放「清除本地数据重开」，存档出 bug 也不会卡死。
- 进入备战时，关掉所有弹窗。

## 7. 复用计划（省资源）

| 模块 | 做法 |
|---|---|
| 工程 | 拷奇兵列阵的 `vite.config.ts`、`package.json`、单文件打包脚本；产物是单文件 HTML，双击就能玩 |
| 美术 | `unitArt.ts`、`duelyst-units.css`、像素字体、`pixel.css`、阶层光效 CSS（`card-tiers.css` 里光点那部分），只拷要用到的单位图 |
| 界面 | `dom.ts`、`tip.ts`、`kwtext.ts`、`icons.ts`、`audio.ts`、卡面 `card.ts`（删掉装备和修炼的字段） |
| 商店 | 照搬 run.ts 里 SAP 经济部分（货架、刷新、锁定、合并升星、升星奖励），去掉备战席和装备 |
| 战斗 | **重写**引擎（碰撞制规则简单得多，大约 300 行），事件格式尽量对齐奇兵列阵，方便复用 `playback.ts`、`fx.ts` 的表现函数 |
| 存档 | 参考 run.ts 的版本号和校验做法；新 key，和奇兵列阵存档互不影响 |
| 暂缓 | 教学镜头、图鉴演示、将军特效、Boss 规则界面，等核心好玩了再拷 |

原型的验收只看一件事：打 10 场，能不能感觉到「我这队越滚越强」。
