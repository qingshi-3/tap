# 逐卡审查（执行方案阶段 1 ①）

94 张商店卡逐张过一遍，一次处理三件事：**换独立形象、重新命名、设计金色技能升级**。按流派分批：每批先出对照图和表，审过后落地代码。规则以源码为准；本文件是审查过程的工作表，全部落地后只保留原则和结论。

对照图在本地生成，不进仓库：`source/output/card-review/current-cards.png`（现状总览，同色框 = 共用同一形象）、`proposal-sample.png`（第一批现状 → 建议）。

## 1. 原则（待确认）

### 1.1 形象

- 每张商店卡一个独立形象，不再共用。素材库 `assets/duelyst-unit-sheets` 还有 265 张未用（SYSTEMS.md §6）。
- 共用形象时，保留给名字和职能最贴的那张卡，其余换新。
- 同一流派尽量题材或主色相近（如补给全是雪原生物），作为加分项，不强求。
- 各阵营的 `*_general`、`*_altgeneral`、`*_tier2general` 预留给英雄（会上场的英雄）和 Boss，不给普通卡。
- 特效、投射物、部件、换色重复类精灵不用（如 `neutral_fog`、`neutral_jaxtruesight`、`neutral_minijax`、`neutral_mechaz0r*` 部件、`neutral_pandoraminion*` 换色、`neutral_prismaticillu*`、`neutral_spellspark`）。

### 1.2 命名

- **名字说"它是谁"，看图能对上；"它做什么"交给技能文字。** 现在的问题主要是职务名配怪物图（分餐官是霜鬼领主、磨粮师是灵狼）。
- 2–4 个字；少用"…官、…师、…工、…员"一类职务后缀。
- 同一流派用统一的题材词（车轮偏骑兵与疾行，补给偏雪原驮队）。
- 不与别的卡同名或只差前缀（现在有"护灯人"和"殿后护灯人"）。

### 1.3 金色

- **身材：从翻倍改为 ×1.5。** 高阶基础身材已按 `TIER_STAT` 放大，金色不再是身材捷径（SYSTEMS.md 决定 5）。
- **技能：卡面单独一行"金色：……"，只改一处。** 玩家在普通卡上就能看到金色会多什么，判断值不值得凑。现在的金色多数只是数字变大（94 张里 90 张），还有 4 张金色技能完全不变。
- 升级类型，优先级从高到低：
  1. **范围**：一个目标 → 两个，身后 → 身前身后；
  2. **次数 / 频率**：每场 2 次 → 3 次，每 2 次交锋 → 每次；
  3. **新条款**：补一个流派语言里的小效果；
  4. **数值**：只用于终结卡或资源产出卡，翻倍或 +1。
- 待定：**并肩**流派以"相邻同名"和"合成金色腾位"为机制，金色规则单独设计，放在并肩那一批里讨论。
