# 排队骑士三合一 v0.9 详细设计与验证计划

更新于 2026-11-11。

当前 `codex/unit-archetype-rework` 实验分支已采用十一套流派、94 张候选单位。实现范围、玩法循环、运行方法与回滚点见 [单位流派重构](UNIT-REWORK.md)。以下章节保留 v0.9 规划和历次实现记录，单位目录以该重构说明及源码为准。

本文件集中记录原设计目标、规则契约、内容方案、验证方法与恢复入口。2026-11-05 用户确认持续养成为主要链路、能力通过通用钩子组合、开放卡池数量，并要求提高第三幕精英与 Boss 密度。本次修订覆盖设计与实施顺序。已交付源码及试玩包的事实记录在第 12 节；批次 III 第一片已实现，后续能力、单位重设计与第三幕结构仍待分批实施。

旧版 `DESIGN.md` 与 `DESIGN-P4-skills.md` 保留方案演变和 P5 第一批实现记录。判断现有行为时以源码为依据，判断本轮拟实现目标时使用本文件。

## 1. 目标、授权与设计基线

### 1.1 已确认方向

- 保留队列自动战斗、酒馆经营、路线、手牌与三连、法术与发现、装备与遗物这些主干。
- 简化补给传承例外、遗物碎片、装备附属管理，控制委托出现频率。
- 内容设计以丰富重玩与涌现为首要目标。单位、法术、装备和遗物通过通用触发与产物相互连接。
- 大多数构筑以持续养成和身材投资建立优势。玩家通过经营提高成长速度，战斗技能、站位与组合决定投入如何兑现。召唤接力和针对性机制保留各自的取胜空间。
- 能力由触发事件、条件、目标、效果、持续范围和状态归属组成。单位、法术、装备与遗物复用这套机制，跨内容连接依赖公开规则。
- 现有全部可招募单位进入新规则下的逐卡设计。原型验证规模与完整卡池设计范围分别管理，新增内容根据全量审查后的缺口安排。
- 卡池数量开放。当前 60 张作为存量审查基线，新增、整合和替换按成长链缺口、独立价值与获取压力决定。
- 中立身份与玩法标签独立设计。中立候选承担通用成长、经营周转与跨机制连接，阵营身份用于角色题材与展示，具体能力读取显式条件。
- 允许少数早期遗物支持低阶阵容走到终局。这类路线出现和成功的频率可以较低，满足条件后应具备真实通关能力。
- 决策随局内进展逐步展开，成型投入应在战斗中得到明显回报。
- 第三幕集中检验已经成型的成长引擎，提高精英与 Boss 密度。固定强敌持续提出身材、输出效率与站位要求，后期保留调整和失败压力。
- 手机横屏是现有项目的界面基线，操作围绕队伍、战场与当前选择组织。
- 视觉基线按用户最新澄清为“紫金主题的奇幻卡牌游戏 UI，搭配精致像素单位与特效”。按钮沿用原版及用户认可的金色按钮参考，使用精致色差、受光层次、厚度阴影和柔光，保留现有交互动效。优化围绕已确认的重叠、遮挡、可读性、点击与焦点问题展开。每次视觉派发分别说明 UI、单位与特效的要求，避免将像素台阶强加到所有控件；按授权提供参考，仅凭提示词的独立试作遵循无参考要求。具体规则与认可参考见 `UI-FX-CONVENTIONS.md`。

先前批次 0、I、II 与攻血上限、关键词修复已交付。2026-11-09 用户授权继续功能优化，交互与视觉优化后续安排；代码按第 12 节顺序从批次 III 推进。规划涵盖现有单位重审、开放扩充、中立候选、能力契约、成长链与验收。表内普通／金色数值为设计候选，已实现能力以第 12 节及源码记录为准。

以下是设计者提出的首轮原型方案，具体取值接受验证结果修订。

| 预计时长 | 暂以熟练玩家 25—40 分钟作为观察区间 | 实测记录战斗、经营、选择和整理各自耗时 |

### 1.3 可观察的体验目标

1. 玩家早期能根据遗物或关键发现改变购买、升本或路线选择。
2. 同一个核心有多个可行的组件组合，同一个组件能服务多个核心。
3. 中途获得新内容时，玩家有理由重新评价已有单位与资源。
4. 低阶单位能通过技能、培养与特殊遗物承担后期职责。
5. 成型队伍能明显压过部分普通战斗，精英和 Boss 通过机制检验构筑。
6. 玩家能说明一段连锁的触发来源、收益与代价，并能在下一局主动尝试变体。
7. 补给、施法、买卖、回合积累与战斗积累各有可启动的成长链，玩家可以提升其中至少一项的单位资源收益或触发频率。
8. 同一培养对象能够接受两种以上成长来源，同一成长引擎能够服务两种以上战斗用途。组件缺失时可以改变获取方式或收益分配。
9. 关键单位的留场价值来自累计投资、技能与配套，换掉它的成本和收益都能从战报及成长记录中说明。

## 2. 设计流程与阶段出口

成熟的流程通过逐步增加成本来验证假设。每一阶段都留下可检查的产物，上一阶段的关键问题解决后再扩大量级。

| 阶段 | 本项目要完成的工作 | 阶段出口 |
| --- | --- | --- |
| A 目标与现状 | 明确用户体验目标，核实已实现规则、旧方案与已知限制 | 确认目标和现状差异，形成同一份活动文档 |
| B 规则契约 | 写清经济、时钟、持有、触发、成长、失败、存档与随机规则 | 同一案例能由设计、实现和测试得到一致结果 |
| C 内容模型 | 定义触发、产物、目标、成本、来源和放大方式，形成内容连接表 | 每个新增内容有明确用途、配套与替代路径 |
| D 完整原型 | 做出能从开局走到结局的经营、战斗、奖励和持久化闭环 | 使用真实输入完成整局，关键状态可解释和恢复 |
| E 策略验证 | 用固定种子、多策略 bot 和真人试玩检验经济、难度与涌现 | 发现主要失败原因，修正规则或内容后复查 |
| F 内容扩充 | 按组合缺口增加卡牌、敌人和节点变体 | 新内容产生新的决策或配套关系，获取渠道同步充足 |
| G 体验与交付 | 审查目标视口、操作路径、文本、表现和性能 | 本轮受影响界面完成实际渲染和交互验收，产物与源码对应 |

上一轮已交付存量卡池设计、规则基础与首个组合原型。本次按持续养成重新完成 B/C 的规划修订，具体能力和案例在第 6 节，实施验收在第 9、12 节。历史完整对局与界面证据覆盖各自记录的源码版本，新方案的数值与体验继续通过原型验证。

## 4. 一局流程、资源与地图

### 4.1 三种计时

| 计时 | 推进条件 | 关联机制 |
| --- | --- | --- |
| 经营轮 | 完成一个节点后进入下一轮，Boss 重试也产生新一轮 | 基础金币、升本降费、回合结束成长、英雄技能次数 |
| 实际战斗 | 完成一次正式战斗结算 | 历战、军团、驻守、佣兵期限、战斗委托 |
| 战斗交锋 | 自动战斗内部的对撞步骤 | 攻击、受伤、阵亡、召唤与战斗持续效果 |

每幕六层加 Boss。各条路线占用相同层数，非战斗节点消耗其中一层。成长型队伍可选择安全经营，战斗成长型队伍可通过交战积累。路线比较采用相同层数下的风险、资源和最终战力。

### 4.2 单轮顺序

1. 进入新经营轮，恢复本轮金币，降低升本费用，刷新未冻结货架，结算回合开始产物。
2. 选择当前可达节点，查看敌人或特殊服务。节点预告在地图上可提前阅读。
3. 自由经营，包括招募、购买法术、上场、整理、施放、合成、换装和升本。
4. 点击主要推进操作，先处理已有待选与待领，再提交回合结束能力。提交后锁定本轮经营动作，并保存提交标记。
5. 战斗节点进入自动战斗。非战斗节点结算对应服务或奖励。
6. 结算永久成长、生命、节点奖励和早期遗物。奖励拥有稳定实例，保存后继续领取。
7. 推进地图，进入下一经营轮或本局结束。

商人特殊库存从进入该节点起开放，与常规酒馆共享本轮金币。营火训练和事件结果在经营结束后兑现。节点收益说明应反映这个时点。

回合结束能力或节点服务产生的新发现与奖励先处理完再推进。此时允许领取奖励、明确放弃奖励，以及无收益放弃已有手牌腾位。放弃手牌单位返还装备到有容量的背包，按 0 金处理且不触发出售能力。`endTurnCommitted` 随存档保存，继续推进与页面恢复均沿用已提交结果，防止重复成长。首战遗物的投放属于新版批次 IV。

### 4.3 节点职责

| 节点 | 常规收益与决策 | 取舍 |
| --- | --- | --- |
| 普通战 | 胜利使下轮额外 +2 金，获得参战相关成长 | 承担 1 心败战风险，换取资源与战斗成长 |
| 精英 | 胜利选择一件装备，进入较稀有装备池 | 败战扣 2 心，事先展示主要机制与奖励类别 |
| 营火 | 原方案为回 1 心、永久 +4/+4、非金色单位 +1 份三选一；新增核心加工原型见 §6.10.5 | 一次营火领取一项收益，休整、升星和加工竞争同一次奖励 |
| 商人 | 特殊装备、定向发现或遗物机会 | 与本轮招募和升本竞争金币 |
| 事件 | 变形、能力加工、有限期交易、低频委托 | 显示代价、收益与持续期限 |
| 宝藏 | 下轮额外 +4 金 | 预留下一轮的升本或集中采购空间 |
| 守关 Boss | 第三幕中途检验阵容，胜利领取指定节点奖励后继续本幕 | 败战扣 2 心并留在节点，平局也留在节点 |
| 幕末 Boss | 前两幕胜利给遗物三选一并进入下一幕，第三幕终幕 Boss 胜利结束本局 | 败战扣 2 心并留在节点 |

营火加份数从旧稿的 +2 调为首轮提案 +1，目的是使普通单位仍需要补件即可变金色。用实际合成频率和低阶路线验证后定值。

前两幕每条路线至少包含三个普通或精英战斗节点，另加幕末 Boss，提供可避开精英的路线。第三幕采用 §4.6 的专用结构。每幕幕末 Boss 前安排营火。生成器逐条验证可达完整路径，重试生成耗尽时使用符合该幕约束的模板。

### 4.4 幕的职责与培养窗口

- 第一幕建立可运行的队伍。首战遗物和低阶组件提供方向，少量发现允许提前接触关键卡。
- 第二幕形成主要资源或战斗循环。路线奖励开始承担定向补件、能力加工和转型。
- 第三幕通过连续精英、守关 Boss 与终幕 Boss 检验成型阵容，要求玩家继续投入成长并根据预告调整站位、辅助和装备。

记录核心开始发挥作用后剩余的正式战斗数。首轮观察目标为至少四场有意义的战斗，其中含一个 Boss。这个指标用于诊断内容投放时机，实际地图长度根据试玩调整。

### 4.5 敌人规则

- 生成输入使用本局种子、难度、幕、层、节点类型和遭遇模板。
- 本幕地图生成时固定节点的敌阵定义、属性预算、机制及战斗随机种子。存档保留生成结果。
- 玩家队伍、遗物、连胜和最近模拟胜率从正式敌人生成参数中移出。离线模拟继续用于设计校准。
- 普通战包含发育、标准和挑战三档预设遭遇，地图展示类型。配比作为表驱动参数。
- 精英拥有明显机制与较高奖励。Boss 基础强度按幕固定，重试沿用同一敌阵和战斗种子，玩家用经营调整解决问题。
- 强度变化首先调整模板预算、机制组合、阶段投放和失败代价。普通模式先验证可承受的一至两轮经营投资。
- 战斗平局延续现有交锋上限规则，普通节点照常前进，Boss 平局停留。继续记录平局是否成为刷成长的优势策略。

本轮已固定节点敌阵底稿与战斗种子。混沌契约等公开事件代价在进入节点时对底稿副本施加一次，重试沿用对应状态，底稿保持可重放。普通遭遇三档标注与投放配比留待关卡校准。

### 4.6 第三幕强敌结构（待实施）

第三幕首轮采用七节点、六场战斗的结构。每条完整路线经过 2—3 场精英、1 场守关 Boss、1 场终幕 Boss、1—2 场强化普通战和 1 个营火。成型队伍在这一幕需要持续兑现成长、处理敌方主力并保护自身引擎。

| 第三幕位置 | 节点安排 | 玩家面对的主要决策 |
| --- | --- | --- |
| 第 1 层 | 精英 | 检验进入后期时的身材和核心完成度，奖励补充最后的配装 |
| 第 2 层 | 强化普通战或精英分支 | 根据生命、敌阵预告与奖励选择风险 |
| 第 3 层 | 守关 Boss | 检验当前成长链的输出与生存，允许围绕固定敌阵进行一次或多次付出生命代价的调整 |
| 第 4 层 | 强化普通战或精英分支 | 使用守关奖励补齐终局配置，选择适合自己处理的遭遇 |
| 第 5 层 | 精英 | 检验最终配置，避免连续普通战消耗成型后的玩法时间 |
| 第 6 层 | 营火 | 回血、培养或补份，结合终幕预告确定最后一次投资 |
| 第 7 层 | 终幕 Boss | 完成整局挑战，胜利进入通关结算 |

第 2、4 层的精英分支在同一路径上合计至多经过一次，保证每条路径的精英总量为 2—3。两条常规战分支都可以保留，精英分支提供更高档的装备机会。路径连线与遭遇模板一起生成，所有可达路线都需满足场次、营火与 Boss 位置约束。

#### 4.6.1 遭遇压力与可调整空间

| 遭遇重点 | 敌人配置方向 | 检验与调整 |
| --- | --- | --- |
| 高身材前排 | 较高攻血主力与少量支援 | 检验持续培养的成果，调整伤害集中、攻击转换与前排生存 |
| 后排突击 | 有限次数的开战后排打击与追击 | 检验辅助的生存，调整位置、生命投资、格挡或保护装备 |
| 多段交锋 | 中等身材配合多段伤害、反击或溅射 | 检验护盾、单体承伤与替补能力，调整输出顺序和阵容厚度 |
| 接力消耗 | 有限复生和召唤产物 | 检验总输出与续战，调整溅射、击杀连锁和前后排职责 |

精英围绕一个主要机制编排。守关与终幕 Boss 各自组合一至两个重点，身材预算、技能次数和可用产物共同决定强度。同一局两名 Boss 的主要机制应有区别。候选敌阵优先复用现有单位与共享钩子，专属能力进入相同的来源、事件与伤害规则。

进入第三幕时公开守关与终幕 Boss 的主题、关键能力和固定敌阵。精英分支在选择路径前展示主要机制与奖励类别。预告要能支持至少两种可执行的调整，例如提高辅助生命或改变站位，增加持续输出或换入范围伤害。配套替代的有效性用实际对局验证。

第三幕敌人按难度、层数、节点角色与模板固定预算，成长结果可以真实拉开胜负差异。离线校准覆盖尚缺一件组件、一般成型、高效率成型和低阶特殊路线，重点提高一般成型队伍面对强敌时的压力。强组合仍可取得明显优势，第三幕的多数常态战斗应保留实际交锋与调整价值。

#### 4.6.2 奖励、重试与推进

- 强化普通战胜利使用常规下轮 +2 金奖励。第三幕精英胜利提供装备三选一，奖励池包含普通装备与奇物，并随层数明确其品质预算。
- 守关 Boss 首次胜利提供装备三选一，候选至少含一件奇物，并使下轮额外 +2 金。装备先沿用既有品质映射，装备分类完成后使用相应统一定义。奖励领取或明确放弃完成后进入第 4 层。
- 守关 Boss 失败扣 2 心，仍存活时留在原节点。平局保留生命并留在节点。每次结算后进入新经营轮，刷新收入、降费及其他轮次规则。重试计入真实战斗次数，成长与临时效果清理按该次战斗结算一次。
- 每次正式尝试有独立的战斗结算 ID，同一结果重复提交幂等。胜利奖励使用稳定节点奖励 ID，每个节点只发放一份。广告回退重打恢复完整开战快照，回退的成长、生命和奖励随快照一起恢复。
- 节点保存独立的 Boss 角色，区分中途守关、幕末过关与终幕通关。守关胜利推进本幕，前两幕幕末胜利切幕，终幕胜利结束本局。生命归零先进入失败结算，保心恢复仍遵循对应节点的推进规则。
- 两名 Boss 各自保存定义、敌阵与战斗种子，失败、平局、重载和界面预览沿用同一底稿。待领奖励中断恢复后继续同一奖励及推进动作。

第三幕额外战斗会增加战斗成长次数，精英与守关奖励也会提升后续战力。校准同时计入这些收益。平局反复经营、失败后的成长与重复领奖分别进入专项检查，记录对关卡压力和通关成本的影响。

## 5. 持有、施放、合成与成长契约

### 5.1 混合手牌

手牌中的每项有稳定实例 ID 和明确类型。

| 类型 | 持有状态 | 使用与移除 |
| --- | --- | --- |
| 单位 | 原有份数、属性、装备、首次入场标记、附加能力和成长记录 | 上场、换位、合并、出售，沿用单位身份 |
| 法术 | 定义 ID、来源、卡面修饰、获得轮、有效期 | 施放后消耗，主动放弃按 0 金处理 |

首轮采用共享 4 格。单位可从场上回到手牌，返场沿用该实例的首次入场记录。手牌单位暂停回合成长与战斗参与。持续全局遗物照常作用于其明确包含的目标。

购买单位可放进手牌，也可直接部署到合法场位。直接部署依次完成购买和首次入场。购买法术支付一次价格，进入手牌后施放费用为 0。保留“从货架拖到目标”的快捷操作，它以一次事务完成购买和施放。

直接部署只检查目标场位或合并目标，满手时仍可执行。快捷施放直接消费货架法术，满手时也可执行，并享有与从手牌施放相同的触发。将购买物保存进手牌才要求空手牌格。

### 5.2 满手与奖励

- 手动购买前按操作去向检查容量及最终目标。条件不足时操作失败，金币、货架和种子保持原值。
- 施放时先锁定合法目标、消耗法术，再生成效果。被消耗的手牌格可供新产物使用。
- 被动生成和发现奖励溢出时进入待领取队列，记录已确定内容。界面显示来源、数量和领取动作。
- 玩家可领取、明确放弃奖励，或整理手牌后继续。整理触发的新奖励追加同一队列。
- 推进节点前处理完待领取队列。刷新、存档读取和界面开合都复用已生成内容。
- 保存点覆盖动作已提交且奖励待领的状态。中断恢复后从同一队列继续。

经营尚未结束时可以正常施放或整理来腾位。结束经营后的待领奖励遵循 §4.2 的锁定边界，只开放领取与无收益放弃路径。

批量奖励按独立实例保存。金色灯笼狐的一次发现产生两张有各自 ID 的法术，两张共享这次选择的定义与卡面数值。玩家逐张领取或放弃，已领取的实例有持久化标记。魂缚吟者产生的强化骨契在生成时保存 4/4 数值、来源单位和效果版本，之后单位离场或变形仍沿用该卡面数值。

### 5.3 法术与补给

补给是法术的一个内容类别。统一持有和使用操作，保留“吃补给”这个独立触发。

- 从手牌施放一张补给，产生一次施法事件，并对每个实际食用目标产生一次食用事件。
- 入场能力直接喂面包时产生食用事件。额外结算法术效果产生效果事件。
- 购买返金能力读取支付成功的购买事件。免费生成、领取发现和施放库存牌各自有独立来源。
- 临时攻血、格挡与附加战斗效果持续到下一场正式战斗结算。经过非战斗节点仍保留，卡面写“下一场”。
- 法术能否作用于手牌单位写入定义。永久属性和能力加工默认支持，依赖场上站位的回响与临战效果要求目标在队列中。
- 当前九种通用法术的基本用途保留，定价和额外收入按混合手牌重新校准。预言类效果明确指向下一经营轮。

### 5.4 触发边界

| 事件 | 触发时点 | 重复处理 |
| --- | --- | --- |
| 购买 | 金币扣除并获得物品时 | 一个购买动作一次 |
| 首次入场 | 单位实例第一次从货架或手牌部署时 | 返手后再部署沿用已入场标记 |
| 变金色 | 达到三份且等级从普通变金色时 | 发放一次三连发现，在场单位按金色值结算一次入场 |
| 施法 | 一张法术完成合法目标选择并被消耗时，包含货架快捷施放 | 效果复制读取同一施法来源，触发器按事件归属结算 |
| 食用 | 补给直接作用于一个单位时 | 多目标分别产生食用事件，传承转移使用属性变化事件 |
| 战斗召唤 | 战斗单位成功占据召唤位置时 | 继承明确标注的召唤强化，入场经营能力在备战阶段处理 |
| 普通攻击完成 | 真实普通攻击及其伤害、死亡链完成时 | 每次实际攻击一个身份，额外普通攻击另计，攻击附带技能独立归因 |
| 技能伤害结算 | 一次技能执行完成其直接伤害结果时 | 记录执行 ID、施行者、伤害类型和逐目标实际生命损失 |
| 阵亡 | 战斗单位生命耗尽或被明确献祭，并进入死亡结算时 | 保存死因、来源与能力快照，再处理召唤和后续连锁 |
| 战后获得 | 正式战斗结束后形成永久成长或奖励时 | 使用战斗结算 ID 去重 |

“额外触发”执行指定能力的效果体。原始事件的观察者按自身规则响应一次，效果体产生的受伤、召唤等新事件正常进入连锁。例如回响触发灯笼狐的入场，会产生法术奖励，施法监听只记录打出的那张回响。

向全队提供同类持续放大的单位使用最高一档，例如霜冠执政官的入场放大。通过自身事件执行效果的单位按各自条目结算，例如风暴剑圣的受伤响应和沙漏构装的回合结束响应。来自明确标注的遗物、装备和法术的额外次数采用相加规则。每个放大来源记录是否已作用于当前原始能力，额外副本沿用来源集合，保证同一来源在同一次原始触发中只应用一次。

#### 5.4.1 原始事件与效果副本

一张被消费的法术分配一个施法 ID。其效果副本复用该 ID，施法观察者以该 ID 去重。回响产生入场效果执行记录，使用原始入场能力及其可用放大器，随后产生的补给、属性和奖励按对应事件结算。

“每轮第一张法术”的使用标记在执行效果前提交。沙域法老的额外效果产生补给或新的法术时，这些结果沿用已消费的标记。新生成的法术在玩家实际施放时取得新的施法 ID。

同一次原生能力执行产生的多个副本共享放大来源集合。由真实受伤、召唤、食用产生的下一条技能可以拥有新的执行记录，沿父链保留来源信息。每一种新增内容检查这类跨事件回路的净资源变化。首批内容中，法术生成池只提供直接效果，新的法术施放需要新的玩家动作或明确消费来源。

#### 5.4.2 变金色与首次入场

合并继承参与单位的入场历史，只要任一参与单位已入场，合并结果就记为已入场。

- 在场单位变金色时，先确定三连发现，再按金色能力产生一次原始入场执行，接受当前有效的放大器。
- 在手牌中变金色时记录待执行的金色入场，下一次上场时执行。
- 全部参与单位均未入场时，首次入场与待执行金色入场合并为一次金色执行。
- 普通合并未到金色时，只累加份数与成长。
- 回响是单独施放的法术，可在合并动作结束后由玩家使用。

例如，金色灯笼狐一次原始入场提供一次发现并获得所选法术两张。在普通霜冠执政官额外一次与旧日徽记额外一次共同作用下，共执行三次发现，每次获得两张，共六张独立法术。溢出部分进入待领取队列。

### 5.5 目标、顺序与随机

- 玩家指定目标优先，普通入场默认作用于最近身前友军，无身前目标时使用最近身后友军。
- 同一时点的我方能力按队首先后结算，来源相同时按能力登记顺序结算。附加能力在原生能力之后。
- 额外触发沿用原能力选择的目标，目标消失时跳过该目标。标注“随机”或“寻找新目标”的效果每次重新取合法目标。
- 阵亡处理先记录同批死亡单位及其能力，再按队列顺序处理。召唤占用释放后的位置，容量不足遵循现有队列规则并记录失败原因。
- 阵亡能力的身前／身后关系读取该批死亡发生前的有序战斗实例快照。首次执行时沿死亡者对应方向筛选仍存活的原队列实例并锁定目标，额外副本及主母代执行沿用该目标，目标离场则跳过。连锁中新召唤与复生实例参与之后新事件的选目标。阵亡召唤的位置继续使用死者释放位置及空位规则。
- 预览读取状态快照和独立随机流。正式经营、奖励和战斗采用可重放的种子或分流标识。
- 所有批量统计记录游戏规则版本、内容版本、种子、策略与难度，复现时使用相同输入。

### 5.6 三连与附加能力

三份同名普通单位手动合并为金色，原有永久成长累加，基础攻血采用金色值。奖励阶级在发生三连时锁定为当前酒馆等级 +1，封顶 6 阶。

现行能力加工与前述逐卡方案以一个永久附加能力位置为比较基线。§6.10 提出独立于升星的两个永久强化槽原型，通用永久能力与少量单位专精共享强化槽。原生技能、装备、永久强化和下一场临战状态分别记录来源与有效期。骨契、铭刻、荆棘印、萌芽印进入永久加工范围，点火和苦修导师按临战状态规划。

- 合并时，一方拥有附加能力则保留它。双方能力 ID、持续类型和数值完全相同时合为一项。持续类型相同且各项数值均较高的一项直接保留。
- 双方为不同永久附加能力，或数值各有优劣时，在提交合并前选择保留哪一个，取消选择则取消整个合并。临战状态另按来源、数值与次数合并。
- 同种等强或更弱的能力赋予被视为无收益目标，目标选择阶段直接提示。
- 变形保留附加能力，原生技能随新单位定义更新。低阶遗物按当前单位定义的阶级判定。
- 金色与额外触发分别处理。附加能力使用自己的固定数值，受适用的触发放大器影响。
- 复制单位时按该效果指定的复制范围创建新实例。首次入场、复制来源、装备及能力是否复制必须写明。
- 复生继承该战斗单位的原生和附加能力，复生使用次数按现有战斗规则消费。

替换永久附加能力会移除原能力，确认界面展示被移除的效果与来源。临战状态持有到下一场正式战斗结束，移动、合并与变形沿用该到期条件，非战斗节点保留。叠加状态把各份次数相加，每次伤害独立结算，来源记录可追溯。复生继承本场尚有效的状态，正式战后统一清理。

首批复制来源分别遵循以下契约。

- 灯笼狐金色复制所选法术及其已确定的卡面修饰，创建两个独立实例。
- 金焰方尖碑金色生成两名普通的一份单位，拥有基础属性和全新的首次入场身份。
- 复刻法术只增加目标一份并调用三连规则。
- 回响与沙域法老复制效果执行，消费标记和施法 ID 按第 5.4 节处理。

已实现与已规划的永久能力包括阵亡召唤、开战伤害、受伤反击及回合成长，具体实施状态见 §7.2。临战状态包含开战自伤和普通攻击前自伤。转授与传火石按声明查询永久加工对象，余温石读取实际下一场效果目标。两个强化槽与专精的资格及继承按 §6.10 验证。

### 5.7 成长系统分工

经营主链依次经过资源获取、触发成长、分配与放大、战斗兑现。多数成型队伍同时拥有持续成长来源和能利用该成长的战斗载体。成长辅助占用五格中的场位，其当下战力损失与后续收益一起评估。

已实施属性契约：攻击与生命没有 50 点玩法上限。永久成长、临时增益、装备换算、战斗副本、召唤、预览与有效 v3 存档保持超过 50 的数值；统一沿用原有 `STAT_CAP=9999` 技术边界。装备诅咒、百分比伤害、固定敌阵预算等其他规则保持各自语义。固定敌阵生成器的单卡攻血分配属于敌人预算，不用于截断玩家属性。

| 成长载体 | 本轮职责 |
| --- | --- |
| 单位永久攻血 | 承载补给、培养、入场和永久技能投入 |
| 历战 | 现行按 hurt 标签与阶层分档结算，目标迁往显式成长能力及可投资强化。新规则以触发成本和效率管理成长，历战阶层累计档位随迁移退出，详见 §6.10.1 |
| 军团 | 现行全局召唤加成为已实现基线，目标由可培养的召唤加成、遗物和能力实例承担，按 §6.8 的召唤投资方案统一迁移 |
| 养蛋与驻守 | 具体单位的成长或产出技能，进度跟随实例 |
| 附加能力 | 改变一个单位能触发什么，以及产生什么结果 |
| 遗物 | 改写经营或战斗规则，为整局提供方向 |

新内容把每份成长明确归给单位、能力实例或玩家持有的效果。受伤、召唤等玩法标签服务检索与统计，触发资格从能力定义读取。迁移历战与军团时先比较同等投资下的战力和成长速度，完成补偿设计及存档版本策略后再切换，现行试玩证据仍按历史规则解释。

永久成长记录实际攻血差值，临时成长单独记录。回合成长覆盖经营轮，战斗成长要求真实战斗事件。属性转移、能力加工和效果放大作为所有成长来源共享的连接点。具体事件口径见 §10.1，完整经营链见 §6.8。

补给传承改为一对可预览的永久攻血记录。记录直接补给效果实际增加到该单位的永久攻血，包含补给自身倍率，继发单位技能产生的增益各自归属技能。

出售带传承的单位时，将记录值的一半向下取整交给目标。场上优先最近身前，随后最近身后。从手牌出售时交给队尾。目标为空时显示无传承对象。转移作为永久属性变化结算。

这一提案将补给历史收敛为可预览的累计攻血，喂养、出售时机和目标选择共同决定收益。旧格式只有在能够证明记录等于实际直接永久增益、并能确定当时倍率时，才转换到新账。缺失历史与已经丢失的成长保留为未知，支持旧规则运行的版本继续按旧定义结算，其余局保留原件并提供新局入口。历史补给传承转换按独立规则验证。

### 6.1 内容共同描述

再分别记录成长角色与战斗用途。成长角色包括资源来源、事件发动、收益转换、培养对象和效率放大，战斗用途包括前排交锋、反击、追击、开战打击、接力和召唤。两者允许多选，逐卡表的连接列负责指出可接入的实际来源。

### 6.3 全量设计范围与原型范围

存量设计覆盖当前全部 60 个可招募单位。每张重新确定职责、阶级、普通与金色能力、获取位置、成长价值和连接关系。攻血与技能数值在统一经济和敌人曲线下重新校准。扩充按机制缺口推进，§6.5.10 给出本次中立候选，总量随验证结果调整。

“保留机制”表示该机制经过审查后仍有明确价值，其阶位、强度、目标规则、金色收益和新系统兼容性继续接受全量验证。“重构”表示需要调整技能主体、资源关系或核心职责。职责重叠且缺少独立价值的条目进入合并或替换评审。

首个完整原型从全量方案中选取一组互相连接的内容进行实现。本轮已落实八张单位改写与七个新法术，六个新遗物属于后续候选。现有法术、补给、遗物和装备已补充联动清单。完整版本的内容数量根据整套卡池的角色覆盖、重复程度和获取概率决定。

原先六个新增单位功能已有承接关系，映射见第 6.6 节。本次允许新增承担独立职责的单位，现卡重构与新增一起评估获取概率、操作负担与重复程度。

#### 6.5.7 新定义的共同边界

- 属性转换在备战执行，按实际可转换量扣减并授予。背刺者以 2 点生命为一组，余量保留。额外入场每次重新检查剩余可转换量。
- 风暴剑圣使用受益目标自己的技能、等级、属性和当前站位结算，技能主归属为目标，放大来源记录剑圣。目标需存活并具有原生受伤技能。技能需要伤害值或伤害来源时读取剑圣此次受伤事件，生命扣减归剑圣此次真实受伤。目标如果也是剑圣，引用继续沿身前方向前进，执行记录保留来源链。
- 曙光执政官借用源卡元数据标为可借用的原生战斗能力，涵盖开战、普通攻击前后、其他友军攻击完成、受伤、击杀、阵亡及阵亡响应、召唤响应、技能伤害结算后。执政官成为能力持有者和实际施行者，使用自身属性、位置、普通／金色档位与独立战斗状态，条件中的自己／其他友军相对执政官重绑定。借影步时由执政官监听其他友军实际技能伤害并培养该施行者，借忍者时由执政官响应其他友军普通攻击并选择自己身前目标。源卡的经营、战后结算、开战注册玩家持有效果、借用、代执行、光环与全局放大能力排除，包含剑圣和主母的代执行部分。借到的开战能力在借用完成后执行。源卡附加能力及状态归源单位，执政官自身附加能力与临战状态按通常规则结算。图鉴及目标可借用提示读取相同资格字段。
- 岚影宗主观察其他友军原生或附加开战能力造成的直接生命损失。每个目标的每次正数伤害记录产生一次追击请求，完全吸收的伤害按 0 处理。追击使用独立的派生伤害类型，开战直接伤害观察者只接受直接伤害类型。请求执行时目标已阵亡则跳过，多名宗主按队列顺序分别处理。
- 深渊主母授予的复生与目标已有复生取最高可用次数。同一原始目标的主母标记取额外次数最高者，平级取队列靠前者。标记的已消费状态覆盖目标后续复生实例。同批死亡的主母按已离场处理。
- 目标阵亡时依次处理自身原生阵亡能力、自身附加阵亡能力、仍存活主母的代执行，之后进入复生处理。主母代执行覆盖这两类阵亡能力，采用死者快照、原有位置及其召唤空位规则，技能主归属仍为死者，主母记为放大来源。主母离场后，已授予的本场复生仍保留。
- 阵亡属性收益读取单位阵亡前的攻击和最大生命，临时成长可参与。技能伤害归实际施行者，产生的奖励附带战斗结算 ID。
- 献祭术士在一次开战执行开始时锁定最近身前的存活友军及其攻击快照。献祭对该战斗实例提交直接阵亡事实，死因记为献祭，随后执行原生／附加阵亡、其他阵亡监听、主母代执行及复生。献祭只消耗本场躯体，持有单位仍参与正式回写。格挡与减伤在伤害结算中处理，此次直接阵亡无受伤事件，也无敌方击杀收益。
- 术士在整条死亡链完成后，按锁定攻击授予自身永久成长。术士在此过程中阵亡又复生时，按同一来源身份找到存活实例并授予一次。原生执行与额外副本按 §5.5 沿用已锁定的战斗目标，目标离场后的副本跳过，复生创建的新战斗实例单独拥有身份。另一名术士的独立开战执行重新选择自己的当前目标。召唤与复生均按各自事件处理，本场开战只启动一次。
- 一次普通攻击在建立动作时记录攻击者及队列关系，完成伤害和死亡链后产生攻击完成事件。影舞依据该动作记录的最近身前身份响应，监听者自身需仍存活。忍者按自身执行时的实时位置寻找最近身前受益者。攻击者在该次攻击中阵亡仍有完成事实，攻击前即被消灭且未实际出手的动作跳过。白鬃猎龙另外要求发起攻击的原战斗实例仍存活，复生实例单独处理。
- 影步观察一次原生、附加或装备技能执行的实际对敌生命损失。同次多目标或多段直接伤害合计只产生一次培养，独立追击及真实额外技能执行各有新执行 ID。普通对撞及其附带溅射归攻击伤害。监听执行时施行者与影步都需仍存活，影步给予的纯攻击成长沿属性事件结算。该次伤害使用修改前的快照，后续技能读取新攻击。
- 攻击后和召唤后监听沿队列顺序逐项执行，每项产生的结果先完成其因果链，再继续同层后续监听。队列为前排、影舞、忍者、影步时，影舞先按当时攻击追击，影步响应实际伤害给予成长，再由忍者给予另一份成长。后续追击读取累计后的攻击。
- 白鬃猎龙先检查攻击后的当前容量，再将小兽插入自己的当前身前，其余单位保持相对顺序。小兽采用无技能产物，满位跳过且无召唤事实。猎龙在队首时，存活产物成为下一名前排。产物在召唤监听中死亡会释放位置，该次攻击的产出已消费，下一次实际攻击才有新的召唤机会。熔岩巨蜥在其召唤监听执行时，重新检查自己、被召唤友军和敌方目标，并读取产物当前攻击。位于其前方的巫兽或火山之心先行强化，后方的强化影响之后的行为。巨蜥伤害归巨蜥，召唤归原召唤者，临时产物获得成长时按其本场身份记录。
- 寒冬守望者读取补给直接给予本人的实际永久攻血，按普通／金色的前后目标分配。继发食用技能、养护匠和传承属性各自结算，分配只产生属性变化。纯临战补给及本次直接永久增量为零时，无可分享属性。

- 复生在该次死亡链最后检查容量并消费本次复生机会。空位已经被召唤占用时，记录复生失败，之后释放空位会进入后续正常事件。主母代执行标记与本次复生机会各消费一次。

- 战斗永久生命增加时，存活目标的最大生命与当前生命同步增加实际数值，技术边界按统一入口裁定，登记实际永久差值。永久生命扣减时当前生命至多保留到新的最大生命，具体效果继续遵守其最低生命约束。复生继承已经获得的永久攻血，以复生规则规定的当前生命入场，继承过程沿用已登记事件。例为当前 3／最大 10 的目标永久 +2 生命后成为 5／12，后来以 1 血复生时为 1／12，战后永久记录总计 +2。

- 沙漏构装按身前关系执行目标的回合结束能力。被执行能力产生正常产物，该次执行只处理对应目标，结果进入统一事件与奖励队列。教官每次重新比较属性，蛋每次增加一份积累，方尖碑每次生成一份待领取发现。结束提交后的新奖励在锁定经营阶段处理。
- 基于实际伤害的增长先由伤害结算给出数值。减伤、格挡、致命伤及过量伤害统一采用实际生命损失口径，反击类能力显式读取来源所属方。棘网蛛只响应敌方单位造成的实际伤害。

### 6.7 全量设计的放行条件

1. 存量全部 ID 有明确处置，新增候选有独立职责，基础攻血、费用与技能强度进入统一校准。卡池总量按验证结果调整。
2. 每个核心有可运行的获取路线和至少两组值得测试的配套。关键资源缺失时有替代或转型路径。
3. 同阶单位在来源、目标、时点、成本或产物上有可辨识差异，重复定义进入合并评审。
4. 低阶内容覆盖独立战力、长期培养、廉价发动、周转和针对等不同职责。
5. 5—6 阶提供多种规则变化，位置、产物、资源和技能借用都进入评估。
6. 修改后按阶级重新计算货架、发现和生成池分布，核对可得概率与核心出现时间。
7. 每张具备独立用途与跨内容连接。现有单位案例在 §6.5.8，新增候选案例在 §6.5.10，效果改写时同步案例与获取池。
8. 原型阶段按依赖分批实现，内容放行覆盖全部卡池及其法术、补给、遗物和装备连接。
9. 每条主流成长链在 1—3 阶有启动路径，并能在五格内同时安排培养对象、发动组件与必要生存。高阶提高效率、范围或兑现方式。
10. 同一能力从不同载体提供时遵循相同事件契约，卡面关键词、图鉴、定向发现与实际触发一致。例外通过明确字段及卡面条件表达。

召唤投资沿两种可混合的方式推进。培养蛋或炎鬃战兽本体，将投入带入产物，蛋明确读取永久增益，炎鬃读取阵亡前攻血。三阶巫兽通过施法积累召唤加成，后期火山之心把自身培养传给产物。二阶白鬃猎龙通过存活攻击持续产出，残魂小鬼、幼兽蛋和炎鬃战兽通过阵亡提供不同投入方式的接力。巨蜥把产物攻击转为即时伤害。阵亡额外执行、复生和空位安排决定兑现次数，通用骨契允许任意培养对象增加召唤用途。

旧军团的固定增长在迁移阶段作为比较基准。目标召唤成长由这些可追溯的单位、能力和遗物承载，按投资损失、转型成本与不同节点路线重新校准。旧历战同样交由显式成长组件承担。两项迁移一起检查初期战力与受伤、召唤路线的获取难度。

#### 五格与成长效率的纸面检查

- 买卖链可以用塑师、护卫、学徒周转位和两名前排／输出开始。普通学徒以 3 金买入、1 金售出，净耗 2 金，向指定目标提供入场 +1/+1，再给随机友军出售增益 +1/+1，塑师另得 +1/+1，护卫另得 +1 生命。随机增益可能落在塑师或护卫，逐来源分别统计。卖出学徒后该位空缺，部署已有手牌或另付金币补位的成本一起计入。
- 施法链可以用受培养前排、守卫、狐周转位、法师和一名输出开始。普通狐按 3 金购入、1 金出售换取一次法术发现，获得法术后的施放触发守卫一次。骨契本身增加能力，守卫另外提供永久攻血。生产法术时狐实际占据一格，卖出后可选择四人战斗、部署已有手牌或另购补位。女王等高阶放大器需替换现有辅助，金币和占位成本随之变化。
- 回合链可以用前排、蛋、沙漏、沙嚎者与一名输出成立。没有沙漏时蛋每轮积累 +1/+1，有普通沙漏时积累 +2/+2，经过真实经营轮兑现。沙嚎者根据站位培养本体或前排，短期战力与未来产物分别比较。
- 开战／追击养攻链可以用前排、影舞、忍者、影步、飞镖的五格队列成立。前排每完成一次普通攻击，影舞先追击，若实际伤敌则影步为影舞永久 +1 攻，随后忍者再给影舞 +1 攻。飞镖开战命中后由影步培养。希望主养飞镖时，将忍者放在飞镖之后，承担改变辅助顺序的代价。二阶阶段先用飞镖＋影步启动，三阶补入忍者后，可将普通交锋收益分给指定输出。
- 阵亡养成可以用暗棘、培养对象、祭师及两名战斗单位开始。暗棘自然阵亡后定向养攻，祭师从其他友军死亡积累生命。中期加入术士可选择提前献祭暗棘，把阵亡增攻与吸收收益集中给术士，也可改为献祭已养大的蛋，提前释放产物。主动发动占一格，献祭的前排与其未来交锋收益构成成本。
- 持续召唤链可用队首猎龙、巫兽、巨蜥、保护单位四人队伍，并保留一个空位。猎龙存活攻击后在身前产出小兽，先接受巫兽培养，再由巨蜥吐息。小兽存活落位后接替前排，之后阵亡释放空位，猎龙再次实际攻击并存活才可继续产出。小兽持续存活时承担交锋输出，空位成本继续存在。第一幕可用猎龙和普通队友直接出战，三阶巫兽通过补给等法术投资后提高小兽质量。四人起手与五人满场的即时战力必须配对比较。

上述计算用于检查循环的输入和输出，刷新、特定卡出现概率、实际战斗次数与胜负另做模拟。常规来源也要能形成有意义的成长，稀有遗物放大特定低阶路线。

### 6.10 核心培养、独立强化与体型容量原型

2026-11-09 根据用户确认的持续养成、低阶机制价值、独立于升星的强化与体型容量方向整合。以下为下一版设计原型，当前可玩版和 §6.5 的逐卡比较仍有五格规则。两个强化槽、容量 10、最多 7 个实体及专精效果都是待验证参数。本节规定统一的试验范围与验收，实施时按具体结论更新对应权威定义。

#### 6.10.1 当前事实与成长方向

- 冰晶甲虫当前为食用补给后额外永久成长，冰霜法师当前已经按正式施法给友军下一场格挡，两者的上下级替代问题已完成首轮改写。后续继续检查甲虫的小额高频食用价值，守望者的直接永久属性分享价值，以及法师的临战保护价值。
- 当前历战只对具有 hurt 标签的持有单位结算，每实际受伤两次折算一点成长。1—2／3—4／5—6 阶分别每场最多 1／2／3 点、累计 4／8／12 点，每点给予永久 +1/+1。该阶层差异仍在源码运行，迁移目标是由显式能力与可投资强化管理战斗成长。
- 新成长方案以金币、实际触发、生存、场次、强化槽与专精机会决定培养效率。金色可以改善原生技能，专精改变资源使用方式，持续投入支持低阶主力的终局深度。各能力需要次数预算时在具体能力中说明，并以实际对局验证。

- 当前蛋的养成主要进入 bank 孵化积累，§6.5.4 拟加入的永久攻血继承属于待实施方案。下面专精按该目标方案试算，实施时先验证基础孵化预算再验证分支。

低阶留队的评审要能回答同一份资源放到该单位时，通过哪个机制获得额外价值。试验包括银盾的生命投资、甲虫的食用频次、蛋的产物投资，以及通用单位接受外部能力后的组合。继续培养、寻找放大器、换成另一种核心三个选择按相同经营阶段比较。

#### 6.10.2 强化、升星与专精的关系

| 投资 | 原型职责 | 成本与继承 |
| --- | --- | --- |
| 普通养成 | 累积单位或能力所属的永久投入 | 金币、资源、事件和场次，保留实际来源 |
| 升星／变金色 | 提升基础身材和原生技能档位 | 同名份数与三连机会，按合并契约继承成长 |
| 永久强化 | 首轮试两个槽，提供通用能力与单位加工 | 使用独立的奖励或金币机会，槽内效果与普通成长分账 |
| 单位专精 | 银盾与蛋先各试两个互斥方向，每个单位最多选择一个方向 | 占上述一个强化槽，普通和金色均可取得 |
| 装备 | 可调配的战斗配置 | 现有装备位置与来源，体型变化及规则词条明示 |
| 体型容量 | 决定可同场部署与召唤的组合 | 单位定义、明确改造和队伍容量奖励共同决定 |

专精作为强化池中的专属选项投放，效果使用通用事件、目标、修正与产物模板表达。强化本身没有独立等级树，淬炼对选中槽内符合条件的效果进阶，具体可淬炼参数在效果元数据列明。两项专精均只有机制定义，首轮淬炼资格限有明确可增强数值的通用强化。

三连后从参与实例的强化中选择至多两项，专精组保持互斥，已选效果按各自声明继承。被放弃的槽位常驻修正退出，独立取得的普通永久成长继续由累计账保存。转授对符合卡面资格的通用永久能力操作，专属专精的改换通过核心加工机会处理。复制单位是否包含强化，由复制效果明示；额外执行技能沿用本次来源快照。

英雄／冠军式分支作为另一个载体方案继续评估。原型先处理两张已有单位的专精与通用强化，分支获取可以依托可预期的加工节点和随机候选。英雄分支的具体载体、节点与候选池须在后续单独定稿。

银盾两项都保留原生受伤增攻，专精读取该次原生能力的实际攻击增量，每份合法原生执行分别产生后继效果。普通／金色通过原生档位产生不同增量，专精沿实际值计算。纯补给加攻和其他来源加攻走各自事件。例为最大生命 20，普通银盾原生受伤增加 4 攻，反击造成 4 伤或护送提供 4 护盾；金色原生增加 6 攻，对应 6 伤或 6 护盾。致死事件后银盾已离场时跳过专精后继，护送无合法身后目标时无护盾产出。

蛋先按 §6.5.4 计算本次基础幼龙预算 B，包括初始 1/1、孵化积累和可继承永久增益。双生数量取 2、预算攻击、预算生命三者中的最小整数，保证各产物攻血为正。两只时分别平分攻击与生命，余数给第一只。B 为 9/11 时，依次为 5/6、4/5；B 为 1/1 时只产生一只 1/1。数量和每只预算先锁定，某只落位失败后，其份额按失败结算。

穿透分支在 B 为 9/11 时产生一只 9/11 并带穿透的幼龙。普通和金色均使用相同分支算法，金色依原生养蛋速度形成更大的 B。巫兽、火山之心、遗物和生效规则中的军团对每只成功召唤物正常施加各自增益，来源分开记录。

专精属于持有实例上的强化修正。主母等明确代执行来源沿死者快照执行孵化，读取该分支与 B，再按当时空位逐只落位。复生继承已选择的专精，新的真实阵亡可以再次触发。执政官当前只借用允许的原生能力，具体强化复制资格按其声明处理。临时召唤物的本场收益沿战斗身份记录。

#### 6.10.5 奖励同时支持留核、放大与换核

营火原型增加“核心加工”作为与回血、份数和属性训练互斥的收益入口。合法强化候选包含通用加工及银盾／蛋专精，按本局种子生成并保存，候选不足时展示实际数量。查看候选后可以返回尚未提交的营火选择，整次营火只领取一项收益。加工对象、已占槽位、替换结果和候选方向在提交前可查。

在不改变奖励成本的配对局面中比较三种选择，继续加工已有核心、取得能放大现有资源的辅助、换入承担另一种机制的新核心。营火、精英与商人的候选构成分别记录实际选择率、达到有效战力所需轮数和机会成本。低阶专精的自然获取样本与强制条件样本分别报告。

当前篝火实现仍是 +2 份、+4/+4 或回 1 心，另有英雄相关装备选项；§4.3 的 +1 份和本节核心加工均属于待实施方案。候选的能力变化与现行奖励证据分别验收。

#### 6.10.6 战前命令与卡组的研究顺序

本轮战斗方向采用备战选择并自动交锋。优先完成单位机制价值、独立强化与空间原型，再试少量战前命令。候选意图包括把敌方首次开战直伤从被保护者引向指定存活守护者，以及为具有可改写目标的开战伤害技能指定本场目标倾向。具体目标资格、次数消费和失效回退在小批原型中定义，复用已有临战状态和目标选择入口。

敌阵预告要使玩家能判断哪个环节受到威胁，再用保护、输出目标或触发配置作调整。命令占用相应资源和临战机会，其实际作用在预览与战报中可解释。持续的战中手动打牌和三层战场属于独立架构研究；经营牌组继续作为后续候选，先验证其对当前经营决策的增量价值。

#### 6.10.7 原型验收与推进

1. 比较同等金币、份数、加工次数和可用节点下的低阶机制核心与新购高阶单位，记录原生能力、普通成长、专精、装备及辅助分别贡献多少，覆盖缺组件与转型。
2. 分别验证普通／金色银盾两分支，受伤来源、原生额外执行、实际增量、致死与无目标。检查保护延长战斗是否值得占用强化机会。
3. 验证蛋预算奇偶、最小预算、两方向、主母、骨契、复生及来源同批死亡，分别在五格基线和容量原型中记录尝试次数、成功次数、实际产物及失败原因。
4. 体型变化、强化替换、三连、转授、变形与存档恢复都需给出可预览结果。超容量调整在备战中处理，保留持有实例和已获得投入，合法队伍才能提交战斗。
5. 容量变化时重评 62 张活跃候选及三张移出卡的独立价值，特别统计多实体带来的全队增益、事件次数、装备与强化收益，常规敌阵预算与 Boss 明示例外同步校准。
6. 核心加工奖励与升本、补件、回血比较机会成本；战前命令随后接入固定敌阵的配对试验。手机横屏必须验证实际可读性和操作路径，当前纸面容量与数量参数待该阶段定稿。

旧日徽记适用于卡面列出的入场、开战、受伤、攻击前后、技能伤害结算后、阵亡、召唤后、获得单位、购买、出售、食用和回合结束事件技能。幼兽蛋的回合结束养成与阵亡孵化、影步的技能伤害养攻、行商护卫的获得单位养血均在适用范围内。光环、持续倍率、格挡层数和事件监听本身按原始定义处理，额外结算作用于监听产生的技能效果。

训练旗作为属性效果提交前的修正器，同一份效果应用一次，记录实际增量后发出一条属性变化事件。仅加攻的效果扩大攻击分量，仅加血的效果扩大生命分量。例为低阶目标施加 +1/+1 后实际 +2/+2，施加 +0/+3 后实际 +0/+4。金色只改变原能力的值，训练旗使用同一份 +1 修正。基础翻倍、装备穿脱、战后已经登记过的永久成长回写按各自记录处理。

低阶目标在养护匠身前吃面包，训练旗先把直接增益变为 +2/+2，养护匠随后产生新的纯攻击 +1 效果，经旗修正为 +2 攻，最终合计 +4/+2。两份效果各应用一次训练旗，派生纯攻击事件完成后连锁结束。多目标效果为各实际目标分别保留修正记录。

余温石在一次施法及其额外效果结束后，读取实际产生了状态变化的目标 ID，去重后给予永久成长。一个目标在同一次施法内被多个效果命中仍获得一次成长，未产生有效状态变化或已离场的目标跳过。生成奖励而未作用于单位的法术按无单位目标处理。

三选一先提供一个能通过当前或 1—2 阶可得内容发挥作用的一般选项，再从剩余池加权无放回抽两个。一般权重 4，低阶稀有权重 1。忽略其他有效性过滤时，一次选项出现低阶稀有遗物的概率约为 14%。投放参数与真实曝光率分开记录。

遗物获得后立即生效，已发生事件按历史结果保留，未来合法事件读取新效果。重复持有同名遗物采用不可选规则。候选池不足时展示实际可选数。

### 7.4 装备与商人简化

- 每单位保留一个装备位置，装备可自由换给其他单位。
- 首轮将装备分成普通装备和稀有奇物两类，分别承担基础修正与明显规则变化。旧四档的每件装备按实际效果映射，逐件检查数值和组合价值。
- 背包保留 3 格。满包奖励提供穿戴、替换、明确折价三个操作，折价收益在按钮上显示。
- 精英稳定提供装备选择。商人按本幕预算提供固定库存，金币消耗发生在本轮。
- 遗物碎片改为直接购买一次遗物选择。首轮价格 7 金，每个商人最多一份，同时记录它对升本与招募的挤压。
- 铁匠英雄改为每幕首次获得装备时可以重选该次候选，重选结果固定并保存。它与装备两类方案一起验证。
- 委托保留为中期事件，每幕最多接一份，奖励目标与路线相关。现有三种委托用作基线，观察是否改变经营。

## 8. 低阶通关路线专项设计

### 8.1 成立过程

1. 首战遗物提供少见起点，玩家能读出它适合保留哪类低阶单位。
2. 第一幕通过低阶金色、补给或能力加工建立主要投入对象。
3. 中期依据资源决定继续低本搜牌或升本找辅助，营火与定向发现提供补件机会。
4. 后期低阶主力继续贡献伤害、召唤或触发，高阶辅助可放大已有队伍。
5. 终局敌人检验具体弱点，通关依赖组合、经营和调整。

### 8.2 验证用的三条路线

| 早期条件 | 低阶主力与可替代部件 | 后续成长 | 主要困难 |
| --- | --- | --- | --- |
| 训练旗 | 冰晶甲虫、行商护卫、飞镖手或其他 1—2 阶培养对象 | 补给、施法、买卖、回合和战斗增长任选配套，配合金色与营火 | 资源消耗、成长事件质量与辅助占位需要取舍 |
| 旧日徽记 | 残魂小鬼、暗棘、幼兽蛋，按获取情况组合 | 低阶金色、暗棘永久养攻、蛋培养、阵亡放大及巫兽辅助 | 召唤空间、开战伤害和前排存活影响兑现 |
| 一般早期遗物加多项合适奖励 | 银盾侍卫、风刃剑士或有保留价值的低阶受伤核心 | 血量培养、开战自伤、受伤放大、装备 | 投放与操作要求较高，缺少辅助时需允许转型 |

第三条用于发现额外的组合可能性，其成功条件允许更加苛刻。

### 8.3 分开统计的结果

- 看到相关遗物的局数与比例。
- 选择该方向的局数，以及选择时已有的单位和资源。
- 获得足够组件并形成可运行循环的局数。
- 成型后的通关率、主要失败节点和操作失误。
- 所有通关中由低阶单位承担主要职责的比例。

五格基线中的“低阶主力通关”按终局至少三名当前 1—2 阶单位且具有主要机制贡献统计。容量原型另外记录持续保留的低阶核心、低阶单位数量、占用容量比例和伤害／保护／触发贡献。通用强化与单位专精沿单位当前定义计阶，转生后的单位按新身份统计。附加能力与召唤产物追溯到原始单位。

这个定义只用于分析样本。关键种子至少展示两种不同配套能完成同一路线，并展示缺少条件时可行的转型选择。成功频率依据曝光、选择和成型各阶段分别解释。

## 9. 涌现、循环与平衡验证

### 9.1 组合检查方法

对每条候选循环列出触发、输入、输出和一次循环后的净变化。

- 买卖单位循环通常消耗净金币，并占用场位和操作次数。
- 回响生成法术消耗回响本身，法术生成池通过内容定义保持可检查。
- 召唤链受阵亡条件、队列空间、复生次数和战斗结束约束。
- 回合成长与驻守受经营轮或实际战斗推进约束。
- 经济循环检查净金币、生命和库存变化，记录任何可重复的正收益路径及其前提。

出现强组合时先记录形成条件、投入成本和反制空间。需要收敛的循环通过明确资源或次数修改相关内容。引擎保留事件预算作为异常保护，触发预算时输出来源链和复现种子，保留最近有效状态，并报告异常结果供修复。

新方案额外检查每条成长链的净永久产出、每金币产出、每场位产出及跨轮加速。自动效果循环区分有实际消耗的新事件与属性派生传播。养护匠的永久生命转攻击具有自然终点，训练旗只提高原本为正的分量。引入反向自动转换时，先验证组合后的净资源及终止条件，再确定相应内容的成本。可持续的正反馈允许强度加速，零成本无限产出需要在具体组件上解决。

异常保护触发后，该次模拟标记异常并保留诊断，正式事务回到动作前可恢复状态。已校验通过的存档继续保留。事件预算属于故障保护，其次数与任何卡面平衡数值分开。

### 9.2 评估矩阵

| 维度 | 至少比较的情况 | 观察 |
| --- | --- | --- |
| 经济路线 | 快升本、中速、低本周转、集中培养 | 花钱结构、投资窗口、最终回报 |
| 内容起点 | 一般遗物、低阶稀有遗物、互相弱关联的候选 | 方向形成、转型率与卡死原因 |
| 路线选择 | 战斗偏多、成长节点偏多、追精英、保生命 | 同层数收益与风险 |
| 获取条件 | 自然随机、强制给起点、强制缺一个关键组件 | 区分获取不足与组合本身无效 |
| 放大关系 | 普通/金色、单一/多个不同来源、附加能力 | 次数、来源归属、有限性与表现 |
| 操作能力 | 自动策略、熟练真人、首次接触玩家 | bot 盲区、理解负担、实际操作成本 |
| 成长方式 | 补给、施法、买卖、回合、战斗分别起步 | 每轮增益、净金币、场位、成型时点、跨轮加速与终局兑现 |
| 卡池扩充 | 存量池、候选加入池、替换重复职责后的池 | 关键入口出现时间、定向发现有效性、空刷与卡死原因 |
| 培养对象 | 相同投入分别进入交锋、反击、开战、追击或召唤载体 | 成长利用率、角色差异、低阶留队与转型损耗 |
| 第三幕压力 | 两精英与三精英路线，守关与终幕的不同机制组合 | 逐层败战、生命消耗、交锋数、关键主力损失、玩家实际调整及奖励收益 |

### 9.3 必要行为用例

1. 满手买入失败、合法快捷施放、生成溢出、待领时存档恢复，均有一致结果。
2. 单位首次上场、回手返场、合金色、能力回响、战斗召唤各自触发正确。
3. 合并与转授在取消、目标失效、能力冲突时保持状态完整。
4. 金色、关键卡、低阶遗物与附加技能同时存在时，次数与目标符合规则。
5. 同一种子和相同操作序列产生相同货架、发现、敌阵和战斗结果。
6. 预览、图鉴演示和候选评估使用快照，正式经营与战斗随机流可重放。
7. 战斗中阵亡、召唤和复生的临时状态在战后按契约清理，永久成长只回写一次。
8. Boss 重试、平局、致命失败和奖励中断都进入明确定义的下一状态。
9. 低阶关键遗物分别有可复现的完整通关样本，并能解释关键投入与失败变体。
10. 普通模式的一至两轮投资选择存在可承受样本，成型后出现明显优势战斗。
11. 同一能力由单位、遗物或附加能力实例提供时，事件资格、目标与效果一致，所有权和持续范围按定义处理。
12. 攻血变化返回实际前后差值，纯攻击变化与纯生命变化分别筛选，每份效果对每个实际目标应用一次训练旗，养护匠产生可追溯的后继攻击增益。
13. 永久战斗成长在战中生效、战后只回写一次，战斗内阵亡、复生、临时召唤与预览分别按身份和作用域验证。
14. 累计成长、临战状态、战后待领与回合结束执行位置可恢复。教官每次读取当前永久属性，沙漏和法老的额外效果按声明读取输入，恢复结果与连续操作一致。
15. 阵营、中立身份与玩法标签独立，变更视觉归属后，同一能力的实际事件资格保持由显式条件决定。中立候选进入商店、发现和允许的随机池并可正常三连。
16. 枚举第三幕全部可达路径，验证六场战斗、两至三精英、第 3 层守关、第 6 层营火与第 7 层终幕。生成重试耗尽后的模板满足同一约束，第 2、4 层精英分支在同一路径上至多出现一次。
17. 守关胜利只进入第 4 层，终幕胜利结束整局。失败、平局、生命归零、保心与快照重打按节点角色正确处理，重复结算与重载领取均只生效一次。
18. 第三幕两名 Boss 各自拥有固定定义、预算和种子。玩家升本、成长、换阵或重试后底稿一致，分支预告与实际遭遇一致。
19. 影步对同次多目标技能只培养一次，独立追击分别培养。全格挡、友伤、普通攻击、施行者离场分别检查。两个影步与金色额外执行分别记录来源和实际增量，比较同预算下的成长速度。

### 9.4 数据与真人试玩

现有模拟入口和统计框架可复用，策略需要增加遗物价值、法术保存、入场顺序、能力加工和低阶投资。现有 bot 的阶层固定加权与随机遗物选择只作为旧基线。

每次批量统计分组报告样本数、难度、策略、种子范围、均值与波动。以固定种子的配对运行比较单项规则变化，控制内容和对手输入。自然运行和强制条件运行分别保存结果。

真人试玩记录实际点击、拖动和结果，重点观察玩家在哪里改变计划、哪里只是在反复整理、哪里无法解释收益。由不同熟悉度玩家覆盖开局、中期和终局。首次原型先收集问题与行为，再确定可用于后续回归的时长和频率阈值。

每条主要成长链分别产出自然获取的整局样本、缺少一个主要组件的替代样本与至少一条跨机制连接样本，说明所用版本、难度、种子和策略。额外的强制局面用于定位效果与目标边界。对局报告追踪成长来源的实际贡献和持有实例的培养轨迹，新增候选数量及过去样本的通关与本轮平衡结论分别记录。

第三幕以相同进入状态和固定遭遇做配对试验，比较旧密度与新密度、两精英与三精英、一般成型与高效率成型。记录额外战斗成长和装备奖励后再分析净压力。真人重点记录看到预告后是否调整、哪些战斗几乎无损结束、哪些失败能追溯到可处理的弱点。多数样本在后期仍连续无损时，调整固定敌阵预算或模板组合，并复查低阶路线与投资期的可行性。

### 10.1 通用能力与事件契约（分批实施）

2026-11-10 批次 III 第一片已实现中央 `AbilityDef` 元数据与显式 `Faction`，以及经营动作和永久成长事实：事实记录实际差值、来源和父链，完整操作结束后发布，观察者异常彼此隔离。事实仅驻留内存，重载不回放，未增加存档字段，仍使用 v3。获得单位在发现进入手牌或待领取队列时触发一次；领取或重载不重复，放弃不撤销获得且不构成出售；免费货架产生获得但不产生付费购买。`battleQueue` 固定战后结算的开战队列顺序，仅对仍持有的实例回写。当前没有战中永久成长生产者，战中响应留待批次 IV。以下完整契约其余部分仍为后续目标。

能力定义包括稳定 `abilityId`、阶段、触发、条件、目标选择器、效果处理器及参数、持续范围、状态类型和显式可借用资格。角色相对条件基于实际能力持有者求值，普通／金色提供参数档位。复杂复制、变形与技能借用由具名 TypeScript 处理器负责，常规增益、伤害、生成、转移与重复执行共用基础处理器。

| 概念 | 契约 |
| --- | --- |
| 已提交动作 | 购买、出售、首次部署、施法等动作携带唯一事件 ID，条件全部通过后提交。取消或失败沿用动作前状态 |
| 动作产生的事实 | 单位获得、食用、属性变化、伤害、召唤、阵亡、授予能力与变金色携带实际结果，条件读取这些事实 |
| 效果执行 | 一次原始能力执行与其额外副本关联，同一份副本沿原规则选目标、扣费用及应用修正器 |
| 属性变化 | 永久／本场区分，记录前值、后值、实际差值与原因。一次效果对一个目标的攻血变化合成一条事实，零增量只保留动作记录 |
| 作用域 | 定义为共享静态数据，运行状态归持有单位、能力实例、战斗实例或玩家持有效果，复制按声明创建独立状态 |
| 来源 | 区分持有者、实际施行者、原始事件、父执行、受益目标与放大来源，保留稳定持有 ID 和阵亡快照 |
| 展示 | 卡面时机、图鉴、搜索、提示和战报从同一能力元数据读取。播放事件由规则结果投影产生 |
| 身份与标签 | 阵营／中立独立于机制标签，能力仅查询显式条件。跨阵营成长与放大可通过通用事件连接 |

1. 每个动作只有一个事实身份。直接购买到手牌、直接部署和购买后合并都记录真实购买及获得结果。免费发现产生获得结果，回响产生能力执行，效果副本沿用原施法身份。一个监听实例对同一个事实按声明触发一次。
2. 回响执行入场能力效果，首次部署的动作记录独立保存。法老重复施法效果，每份副本产生真实食用、伤害或属性变化结果，施法观察者仍读取一个施法事实。女王等放大源在同一次原执行中各应用一次。
3. 同一时点使用稳定队列顺序与能力顺序，原生和附加能力各有执行身份。监听者资格按事件发生时的有效实例确定，执行时重新验证目标。代执行、借用、复制单位分别写明施行者、数值档位、输入事件与状态归属。
4. 永久属性修改统一经过提交入口。转换把扣减和授予原子提交，分享和继承读取明确来源的实际差值。训练旗在提交前修正一次，养护匠在提交后读取实际加血。纯属性连锁保留因果链，新增转换组合以可重复执行的净资源检查放行。
5. 战斗中的永久成长同时修改战斗副本并登记持有实例的实际增量。正式结算按 `settlementId` 一次回写，战中增益沿用原事件 ID、已应用修正器和监听记录。战后能力新产生的增益取得新的事实 ID，并派发给允许战后阶段的监听者。临时召唤物由其本场实例承担效果，回写要求有效持有映射。预览使用独立副本。
6. 跨阶段事件的目标可以是持有实例。战后监听与相邻关系读取开战时冻结的持有队列，战斗中阵亡的原队员在该快照中仍有资格，永久离开持有状态的实例跳过。战中事件按发生时实时队列。养护匠明确支持经营、战斗与战后三个阶段，战痕记录官属于开战注册、战后执行的玩家持有效果，各能力在详情中显示阶段和持续范围。
7. 获得能力、累计成长、临战次数、回合进度、待领奖励和结算去重状态由所属实例持久化。经营动作以校验、提交、结果及待选状态作为保存边界。回合结束保存执行顺序、当前执行位置及已提交结果，教官额外执行重新从恢复后的状态选择当前目标。
8. 先统一元数据与属性入口，再迁移施法、入场、买卖与回合，最后接入战斗事件和永久回写。每迁完一条链，旧入口转发到同一实现并核对行为。展示元数据、规则执行与测试在该链一起迁移。

当前 `run.ts` 的 `onBought`、`onPlay`、`spellObservers` 和 `nativeTimings` 可作为迁移入口。当前 `engine.ts` 的播放事件与 `ShopFx` 继续服务表现，新增领域事件记录明确的因果和生命周期。现有战后去重可复用，规划中的按能力永久战斗成长须补齐引擎输出与归属测试。

### 10.2 存档与规则版本

混合手牌采用带 `kind` 的联合类型。单位、法术和奖励使用稳定身份，代码按类型分派。行动提交前统一校验资源与目标，提交时记录派生效果和待领结果，保存时包括尚待完成的选择。

本轮采用 v3 新局，存档键为 `pdqs3_run_v3`。校验覆盖混合手牌、待发现与待领队列、附加能力、地图敌阵与种子、实例 ID 唯一性、`nextId` 和回合提交状态。成功校验后才恢复游戏。

v2 旧局保留在原键 `pdqs3_run_v2`，首页明确提示使用新局体验本轮规则。v3 键中损坏或不支持的原始内容在覆盖前保存到唯一备份键，备份失败时停止覆盖。已实现支持范围为有效 v3 局，后续若扩展旧局转换，须针对实际格式补充迁移验证。

后续能力结构、累计成长记录、临战状态与历战／军团变化进入明确的新规则版本。保存内容版本与规则版本，保证进行中的局使用可解释的定义。可确定的字段做保留原件的转换，缺少历史的统计从版本启用后的事实开始累计。无法确定转换结果的局提供原件保留与新局入口，具体支持范围在迁移批次验收时写明。
