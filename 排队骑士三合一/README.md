# 排队骑士·三合一

手机横屏 H5 卡牌构筑游戏，计划发布到 TapTap。核心循环：杀戮尖塔式三幕路线 + 超级自动宠物式排队交锋 + 炉石酒馆式经营（升本、手牌、三连、发现）。

本文件是项目的**唯一入口**：1.0 的目标与范围、当前实现、开发方式和文档地图都在这里。规则细节以源码为准，文档与源码冲突时改文档。

## 1. 1.0 目标

**1.0 = 现有系统做到“好玩、稳定、能上架”，不再扩大机制范围。** 2026-11-15 冻结范围：以当前 94 张流派卡池和支援系统为准，v0.9 规划中尚未实现的批次全部移到 1.0 之后（见 §3）。

### 1.1 范围内（已实现，只做修复、调平衡和打磨）

| 系统 | 当前内容 |
| --- | --- |
| 一局结构 | 3 幕 × (6 层 + 幕末 Boss)，共 21 回合；每走一个节点算一个经营回合 |

### 1.2 1.0 剩余工作（按优先级）

1. **平衡**
   - 普通难度通关率：最近一次 bot 模拟（300 局，普通难度，默认老兵队长，能力值 0.65）为 29.0%，终局 Boss 胜率 23%；第一、二幕 Boss 胜率 83%–98%，终局仍是断崖。
   - 后期商店（2026-11-15 第一轮）：原先第 7 回合起 5 个单位里约 4.5 个已是金色，此后每回合几乎不买单位，金币全花在补给上。已加入「接替」（商店单位拖到不同名队员身上，继承永久加成和装备，见 `run.ts` 的 `takeover`），并按阶层放大高阶身材（`reworkCatalog.ts` 的 `TIER_STAT`），满本时 1–2 阶卡出现率减半（`shopTierWeight`）。改动后通关率从 13.3% 升到 29.0%，但第 13–21 回合 bot 每回合买单位只从约 0.2 升到 0.4，后期换人仍少，下一步看金色门槛（低阶卡第一幕就能凑满金色）。
   - 第三幕和终局强度、各流派成型速度、支援品选择效率。
   - 难度梯度：噩梦的敌人系数 `k = 0.82`，低于困难的 `0.95`，和“敌人再强一截”的描述相反，需要确认是有意设计还是错误。困难的说明“手气差时不再放水”描述的是按玩家强度挑选敌人的旧机制，敌阵改为开幕固定生成后，这套机制已经不生效（2026-11-15 已删除这部分死代码），说明文字需要改写。
2. **真人与真机验证**：3–5 名玩家在手机上完整打几局，记录每局时长、卡住的地方和没人选的流派。至今所有验证都来自 bot 和桌面浏览器模拟。
3. **美术缺口**：94 张单位只有 56 种形象，其中 70 张与别的卡共用形象（同一形象最多 3 张卡）；新法术和新遗物借用通用图标。
4. **平台接入**：`src/ui/ads.ts` 里的激励广告仍是模拟实现，需要接入 TapTap 广告；还需要控制包体、准备审核素材（图标、截图、说明、隐私条款）、在真机上验收。
5. **工程健康**：测试入口统一、旧代码与旧样式清理（2026-11-15 已做一轮，见 git 记录）。

### 1.3 1.0 完成标准

以下数值为建议值，可调整：

- 普通难度 bot 通关率落在约定区间（建议 35%–55%），11 个流派都有通关样本。
- 至少 3 名真人在手机上完成整局，没有阻断问题，每局时长在 25–40 分钟。
- 844×390、720×360、1280×720 三个视口主流程无遮挡；`pnpm test` 和 `pnpm build` 通过。
- TapTap 广告接入完成，单文件包体积和加载时间达标。

## 4. 开发

```bash
cd source
pnpm install --frozen-lockfile
pnpm dev            # 开发服务，加 ?debug 可在控制台用 window.__app
pnpm test           # 战斗、经营、存档、支援、目标、教程回归
pnpm build          # 字体子集 + 类型检查 + 生产构建（dist/）
pnpm build:single   # 单文件包（dist-single/index.html）
pnpm sim 200 0.65   # bot 整局模拟，用于平衡
```

- `pnpm test` 是唯一的回归入口，新的规则测试加进这里；测试夹具只使用本局开放卡池里的合法单位（`activeCardPool`），否则 v5 存档校验会拒绝。
- 浏览器回归（`pnpm test:ui*`）需要 Playwright 和本机 Chrome，会写入测试存档，请使用独立的浏览器上下文。
- 分析工具（不属于回归）：`scripts/node-stats.ts`（按节点统计 bot 胜负）、`scripts/demos.ts`（检查关键词和单位演示覆盖）、`scripts/import-hourglass-art.py`（从 Duelyst 图集导入单位帧）。
- 样式的加载顺序就是层叠顺序：`main.ts` 先依次加载全局样式（`style.css` → `pixel.css` → `duelyst-units.css` → `global-layers.css` → …），组件样式随各自的 TS 模块导入，`ui/theme.css` 最后加载。`global-layers.css` 和 `prep-features.css` 是按原顺序合并的历史覆盖层，新样式写进组件自己的 CSS 文件，不要再新建按版本或巡检轮次命名的覆盖文件。
- 一次性的调参、审计实验脚本不进仓库。需要保留的结论写进文档，代码依赖 git 历史找回（2026-11-15 清理前的版本为 `6b525de`）。
- `source/output/` 存放本地验证截图和报告，不进仓库。文档中引用的 `output/...` 路径只在当时执行验证的机器上存在。
- 新增中文文案后需要重新跑 `pnpm build`，字体子集会随之更新。
