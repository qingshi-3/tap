# v2 战斗模块

按《排队战斗系统核心设计文档》v1.1（含 R1～R12）和 `CONTENT-DESIGN.md` 重做的战斗核心，从 `prototype/` 逐行移植成 TypeScript。和旧引擎 `core/engine.ts` 并存，逐层替换（见下方"接入步骤"）。

## 文件

| 文件 | 内容 |
| --- | --- |
| `types.ts` | 单位、战斗状态、日志、卡牌定义、英雄技能的类型 |
| `engine.ts` | 规则引擎：五节点、同步快照、先进先出 + 原子动作防重入 + 深度上限、补位时、插队、援护、召唤、亡语 / 共鸣、坟场、吞噬、复活、障碍物、扩编、冰冻、疲劳、巨型横扫；三名英雄、9 个分支 |
| `cards.ts` | 圣盾、影刃、深渊、霜境各 10 张，中立 4 张，召唤物 3 种，机制敌人 4 个 |
| `teams.ts` | 随机组队（按幕限制阶层和等级）、机制遭遇和遭遇系数 |
| `ai.ts` | 模拟 AI：排站位、整局技、贪心英雄 |
| `index.ts` | 模块入口和引擎开关 `useEngineV2()` |

## 流程

```
createBattle → [heroAct 整局技] → startBattle → [heroAct*] → advance → [heroAct*] → advance … 直到 s.result
```

状态是纯数据，可以 `structuredClone`。每次 `advance` 跑完一整轮（攻击前 → 交锋 → 交锋后），停在英雄操作窗口。播放层只读 `s.log`，每条日志都带当时的快照。

## 命令

```bash
pnpm test:v2
```

和 `prototype/` 逐局对比：同一组队伍、同一种子、同一串英雄操作，两边的完整战斗日志必须一模一样（600 局，覆盖四流派、机制遭遇、三幕、三名英雄和分支）。改规则时要两边一起改，或者等原型退役后删掉这个测试。

```bash
pnpm sim:v2 100 3 0.65 10 boss stage=mid hero=pusher pre
```

战斗模拟，参数和 `prototype/README.md` 一致。

## 接入步骤

1. **移植引擎**（本目录）。旧引擎不动。
2. 改造战斗界面：分步播放、英雄窗口、意图显示；开关打开时走新引擎。
3. 换卡池。
4. 改一局的流程：按 CONTENT-DESIGN 第 3、4 章裁掉旧系统，接上升级、生命、分支选择和遗物。
5. 清理旧引擎和测旧机制的测试。

## 和原型的差异

- 去掉了旧调度者留下的死代码（`regroup` 分支、"双锋"的 `ultArmed`）。`regroup` 已不在技能表里，原型里真被调用会报错。
- `pnpm sim:v2` 的 `focus` 模式从四个流派里抽（原型漏了霜境）。
