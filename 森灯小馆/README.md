# 森灯小馆

手机竖屏、单机普通 H5 餐馆经营游戏。技术为原生 JavaScript ES modules、Canvas 场景与 DOM 交互；宽屏自适应。UI 直接复用本地《奇兵列阵》的像素生成器与相应视觉资源，来源详见 [assets/SOURCES.md](assets/SOURCES.md)。市场参考及实际采用的设计判断见 [RESEARCH.md](RESEARCH.md)，持续任务与验收记录见 [TASK.md](TASK.md)。

## 玩法与内容

采集或采购原料 → 研究并安排最多三道菜单、选择售价 → 自动服务与按需手动补位 → 日结 → 投资设施、员工与新产区。开局160金币、声望10，八种原料各8份；小栗默认在职，每4秒照顾一桌，首日无需先招人。营业持续60秒，无付费等待或内购；采购面板提供自愿资源激励广告。

- 三产区：晨露森林、芦苇河湾、风车山麓产出不同食材；后两区需要金币与声望开通。每日四点采集行动，可先分配各产区次数，再一次出发；菜园与采购员工只增加主产物，天气改变实际产量。
- 十二道菜：初始三道，其余九道同时受阶段、声望、研究金币与材料约束。实际卖出次数提升熟练度并带来溢价；菜单不是按日期自动全部解锁。
- 十种每日事件：两分支明确预告资源代价，分别影响来客、售价、耐心、烹饪、小费、库存或声望；同一天只能选一次。
- 八类原料订单：每三天出现新机会，接受后有两至三天交付期限；交付消耗真实库存，与菜单和研究竞争材料。订单逾期不罚到破产，完成订单不能重复领奖。
- 员工与设施：四名员工最多两名当班，只有在岗者发挥专长并领取工资；小栗快速服务，苔苔加快烹饪，露露增加小费，老橡降低采购成本并增加采集主产物。老橡出勤采购或采集后，当天不可休息，次日重新安排；不能先拿采购收益再免费换成服务岗。空班仍有店主基础服务。五类设施各三档升级。
- 客群与定价：赶集客、过路旅人、品鉴客轮换，平价、常价、高价分别改变真实售价与来客速度，界面展示当天基础倍率。固定高价不再适合所有日子。
- 两条扩建：第8天起可购入林边外带窗（客流与周转优势、售价折让）或灯下雅座（溢价、客流下降），各650金；两条均可持有，营业前只能选用一条。
- 六类营业委托：限定菜系、不同料理品鉴、连续多日接待，按真实供应结果推进，与原料订单可并行。未完成到期不罚款；已完成报酬保留至领取，不能重复发奖。
- 四季节庆：第7天送出7份林间料理；第14天河鲜营业额达到300金；第21天至少两种甜点各卖出两份；第28天用暖胃菜接待至少三类客人。按真实结果分档结算：春夏100/180/260金，秋冬按菜品或客群种类设100/180金两档。界面预告具体目标，当日显示进度；失败不发奖励，下一轮四季可重试。

第28天给出本轮结局与真实完成情况，之后可以继续自由经营。季节、天气与客群偏好影响实际采集和收入。备料明显不足时可从开店旁直接补货；营业中彻底售罄且无烹饪、用餐客人后可提前打烊，正常结算当日进度与工资，不必空等。断货、未服务、差评和订单逾期均可恢复；采集行动与资金食材都耗尽时，满足条件可领取每日一次的应急菌菇重新营业。

日结中的“成本”为消耗原料的市场估值加实际支付工资，“利润”为营业收入与小费减该经营成本，**不是金币账户的当日现金流水**。免费采集原料仍按市场估值计入成本；采购、研究、设施、雇佣、事件、订单与目标奖励会另外改变金币。工资最多从当天营业收入中扣除，不会将余额扣成负数或侵占此前的恢复资金。

## 资源激励广告（1.0.1）

采购与产区面板可自愿选择80金币，或蘑菇×6、稻米×6、浆果×4；每个游戏日两类合计最多2次，只能营业前领取。免费采集、应急食材和原内容进度不变，无强制插屏或Banner。宿主未提供广告能力时入口置灰。

仅独立广告请求收到严格的 `isEnded === true` 且存档上下文未变化时发奖；显示成功不代表看完。失败/取消/超时/旧回调均不发奖，失败不扣次数；每次实例独立销毁，最多一次load/show恢复。奖励和请求ID同档提交，保存失败不替换内存资源并暂停、显示导出/重读。

schema 1新增可选 `ads:{day,claims:[{id,kind}]}`（当天最多2条）。1.0.0缺少ads的完整旧档仍受支持，首次领奖写入；ads存在但损坏则拒绝。冻结旧档样本与加载、领奖、保存、重进、继续营业保存回归位于tests/ads.test.mjs。开发者广告位来源及状态见platform/ads-status.json；浏览器模拟回调验证不等于TapTap真机播放或收入结算验证。

## 本地运行与打包

需要现有可用 Node.js；项目无运行时外部依赖。在本目录运行：

```powershell
npm run preview
```

默认本地入口为 `http://127.0.0.1:4194`。测试、构建、打包入口：

```powershell
npm test
npm run build
npm run package
```

当前源码版本1.1.0，打包强制执行经营、存档、广告及新经营规则回归。构建与打包产物以各脚本实际输出为准。本地包不等于已上传、已提审或已上线；实际浏览器与平台验收状态见活动任务和绑定记录。

## 存档契约

仅在本设备浏览器保存，当前 schema 为 `1`。固定主键为 `forest-lantern.save.v1`；覆盖前将上一代有效原件写入 `forest-lantern.save.v1.backup`。备份写入失败会停止主档覆盖。

读取时校验完整结构、内容 ID、数值、经营阶段、订单、节庆与熟练度记录。不支持的版本、损坏或缺字段档会被明确拒绝，原件保留；不会静默重置、猜测修复或自动覆盖。界面提供原档导出与重试入口。多页面发现其他页面更新后暂停写入，避免覆盖另一份进度。

1.1.0增加可选 `operations`：当班员工、采集计划、扩建所有权与当前路线、营业委托进度/完成/过期记录；可选 `procurementCommitted` 记录当日采购出勤锁。缺少扩展的1.0.0与1.0.1完整旧档合法，首次成功经营操作初始化，优先小栗并选已有另一人当班；保留全部金币、库存、员工所有权、设施和节庆成绩。存在但损坏的字段明确拒绝，连续日委托不能记入尚未结算的日期。已完成未领取委托可跨截止日保存。冻结历史样本位于tests/fixtures，覆盖读入、继续营业、保存、重进及再次保存。

当前支持范围为同设备、同固定存储位置、满足现行 schema 1 完整契约的存档继续游玩与保存。不承诺开发中每个临时草稿结构的迁移，也不提供跨设备同步。清理浏览器站点数据会删除本地进度；可使用界面导出保留副本。备份不会自动恢复为主档。
