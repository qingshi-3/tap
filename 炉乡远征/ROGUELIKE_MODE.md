# 秘境远征实施方案

2026-11-05。用户已授权制定方案后本地实现。活动进度与共享文件交接统一记录在 TASK.md。本文件负责模式规则和实现接口。

## 目标与首版范围

为已通关玩家提供可重复的单人构筑冒险。沿用棋盘、移动、攻击、主将技能、召唤、法术、抽牌与疲劳，增加局内牌组、遗物、路线选择和逐级难度。

界面沿用游戏现有 qibing 按钮、主页背景及卡牌组件。遗物与路线信息卡复用存档窗口的像素边框和深紫底板，整块可点选，通过轻微填充变化和勾选标记反馈选择。用户于本轮明确要求统一已有游戏 UI，秘境页不另用自制纹理。手机横屏保持战场和主要操作优先。

每件遗物配置独立图片标识，在候选、已拥有列表及战斗目标中一致展示。稳妥、精英、首领路线分别使用铜色、金色和最高阶银金徽章，保留等级文字。图片复用已授权 Duelyst 资源，映射归 `roguelike-icons.js`，来源和帧记录见 `dist/assets/roguelike/SOURCES.md`。

战后整备和牌组查看采用自适应多行网格，随可用宽度换行，大牌组在内容区纵向浏览。主要操作固定在底部，详情返回恢复选择、焦点和浏览位置。

- 首版三个主将为齐兰、蕾瓦、莉莉丝，分别支持治疗、法术和阵亡召唤方向。
- 每局六战，第3与第6战为首领。普通节点可选择稳妥或精英路线，敌情和收益在进入前可查看。
- 内容目标为12种遭遇模板、4个首领候选、18件实际生效的遗物。复用既有素材和已验证的地图机关，独立配置敌军强度。
- 起始牌组15张，胜利后从三个两张主题卡包中选一个，可跳过。牌库支持12至45张，同名上限6张，允许奖励提供跨阵营牌。牌组限制只对显式标记的秘境战斗生效。
- 每位主将两套起始配置，首次通关解锁第二套。难度1至5，完成当前最高难度后开放下一级，记录各主将最佳通关难度。
- 开局选择一件遗物，精英及中途首领胜利后再选遗物，单局遗物去重。战后整备提供45金币强化与免费继续，按用户选择撤下常驻删牌入口。每次强化作用于所有同名牌，随从+1攻击/+2生命，法术费用-1且最低0，每种牌最多强化2次。强化持续整趟远征，后续战斗与退出续玩均保留，通关、失败或放弃后结束。
- 每场重新部署，主将恢复，累积牌组、遗物和强化。一场失败或主动放弃结束本局，可重新开局。中途返营保留进度。
- 本局金币与成长归属独立秘境存档，永久奖励为新起始配置、难度与通关记录。后续每周异变和同种子挑战基于本局种子扩展。

以上数量和强度为首版设计值，需要完整游玩验证后调整。先交付完整循环，再依据实际卡组和敌人表现调平衡。

## 随机与战斗边界

开局固定随机种子。路线候选、卡牌奖励和遗物候选生成后即写入存档，重进恢复同一选择。候选按阶段、费用曲线、流派标签组合，至少提供当前可用的牌。遭遇使用完整地图与机关模板，敌军方案随本局冻结。

冻结内容包括地图尺寸、地形、出生点、目标、回合上限、敌军方案和机关定义。待开战候选通过 `roguelikeTemplate` 与 `roguelikeMechanics` 成对交给引擎，战斗快照保留同一来源。版本更新后首次开战及战斗恢复均依据冻结内容校验。

战斗保持 mode=expedition、schemaVersion=7，并增加显式 roguelike.version=1 分支。普通与历史战斗走既有校验。秘境规则负责12至45张合法卡组、局内强化、遗物次数及快照验证。禁止依赖永久培养改变秘境强度。

遗物通过已有引擎行为入口执行。所有触发次数和消耗随快照保存，伤害、治疗、召唤沿用引擎接口。预览克隆与真实战斗分别维护状态。死亡、施法、回合等触发必须限制递归，完成终局后停止后续有害事件。

## 存档与失败语义

固定独立键 `duelyst-h5.safe-v1.roguelike-v1`，schemaVersion=1。保存模式版本、主将通关记录及当前冒险，当前冒险保存种子/随机游标、主将/起始配置/难度、阶段、牌库、局内金币、遗物、强化、冻结候选、当前战斗与随机上下文。

写入前比较已读原字节，写后读回确认。失败保留当前可重试状态，候选不重抽。奖励领取、金币扣除与阶段推进单次提交。重复结算同一战斗不再支付收益。损坏、未知版本和并发旧页拒绝覆盖并保留原件。新局素材加载成功后提交战斗，加载失败可重试原候选。

本轮聚焦同设备更新后继续游玩。新增档必须覆盖战斗中、待选牌、待选遗物、整备、通关与失败的加载、继续、保存、重进、再保存闭环。既有历史样本保持冻结。

## 模块接口与归属

- `roguelike-rules.js` 定义冻结遗物目录、局内卡牌强化、显式战斗标记及事件触发，`engine.js` 显式分派秘境规则。
- `roguelike-data.js` 定义主将起始配置、遭遇模板、奖励与难度。`roguelike-session.js` 负责独立状态机、随机、存档与事务。会话执行者独占。
- `roguelike-ui.js` 与 `roguelike.css` 负责主将/起始配置、路线、奖励、整备和结算界面。UI执行者独占新文件。
- `main.js`、`expedition-ui.js`、`index.html` 已在冒险聊天释放后串行整合，主责完成 pixelfx 资源导出、实际输入验收和最终审查。
- 其他聊天推进18关冒险与成就图标。后续共享文件仍按各聊天在 TASK 记录的稳定交接点安排，避免同时写入。

会话接口约定 `start(options)`、`chooseRelic(id)`、`chooseRoute(id)`、`chooseCards(id)`（null跳过）、`camp(action,cardId)`、`prepareBattle()`、`commitBattle(match)`、`checkpoint(match)`、`restoreBattle()`、`owns(match)`、`leave()`、`abandon()`。修改均返回 `{ok,error?}`，开战返回 `{ok,match}`。`record` 为已保存状态，`error` 为可显示错误。`record.run.phase` 使用 relic/route/battle/cards/camp/won/lost；run内包含 `heroId,kitId,difficulty,stage,deck,relics,upgrades,gold,offers,match,context`。UI只通过会话动作写入。
