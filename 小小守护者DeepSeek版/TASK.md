## 本轮修掉的真实缺陷

这些都是在浏览器里打出来的可复现缺陷，不是推测：

1. **所有界面按钮点不动（严重）**。`attachInput` 对卡片/战场调用了 `setPointerCapture`，指针被夺到战场容器后浏览器不再为按钮合成 `click`，于是招募、商店、暂停全部失效；测试还因此出现莫名的重复扣费。已改为不做指针捕获，只用 document 级监听，并用 `blur`/`visibilitychange` 兜底结束手势。
2. **手指表泄漏导致后续操作全部失灵**。隐式指针捕获会把 `pointerup` 重定向到被捕获元素，document 级监听收不到，残留的 pointerId 让之后每次单指触摸都被判为多指。已在新手势开始时清理残留。
3. **短屏选中面板盖住底部指令栏**。`positionContext` 只在定位时用了可用高度，从没把高度约束写回面板，568×320 下面板长到 207px 伸进指令栏，面板内的警戒滑块被压住点不到。已写回 `max-height`，面板超高时内部滚动。
4. **商店列表每帧重建**，销毁正在被点击的按钮并把滚动位置重置回顶部。改为只构建一次、之后原地更新价格与库存。
5. **`renderContext` 每帧重建**，销毁正在拖动的滑块。改为同一对象只原地更新。
6. **HUD 图标按钮短屏只有 30px**，低于 44px 触控下限。已恢复 44px。
7. **首页 `button('open-codex')` 引用不存在的元素**，异常中断整个启动流程，渲染器根本不会被创建。图鉴/记录改为在暂停面板按需生成。
8. 提示条从不显示、经验条是死代码（旧版遗留）本轮未沿用。

## 下一轮要改的（我自己的复查结论）

1. **警戒范围环太抢眼**：现在是多层高亮青色同心椭圆，铺满战场、压过单位和地形。要改成细描边 + 很低透明度的填充，并减少环数。
2. **地表过于饱和且重复感强**：草地是发亮的黄绿，同一格花纹在整张图上重复可见。需要降低饱和度、增加变体分布。
3. **`water` 与 `path` 指向的地景格与草地几乎同色**（`asset-check.json` 里 `water` 与 `grass` 是同一 rect），水面和道路读不出来。需要在 MiniWorldSprites 里另选真正的水面/道路格，或本轮地图避免使用。
4. 建筑（城墙/箭塔/减速）目前直接用地景格，尺寸与风格更像地形贴片而非建筑，需要专门处理。

## 2026-10-15 第二轮：视觉修正（用户验收后的返工）

用户验收后我逐张看真实截图，又查出并修掉一批问题。这一轮我先做了**像素级取证**再改，不再凭感觉。

### 素材映射错误（我继承了错误映射，已纠正）

`public/assets/manifest.json` 里 `water` 与 `grass` **指向同一个 rect**，所以地图上的"水"其实就是唯一的草地图；同时 Grass.png 的几格被认错了。逐格采样实测后纠正（素材执行者执行，我复核）：

| 键 | 源 | rect | 实测平均色 | 不同色数 |
|---|---|---|---|---|
| grass | Grass.png | [16,0] | (195,214,87) 黄绿 | 1 |
| water | Grass.png | [0,0] | (78,188,185) 青 | 1 |
| shore | Shore.png | [0,0] | (231,213,147) 沙 | 1 |
| deadGrass | DeadGrass.png | [16,0] | (184,180,125) 土黄 | 4 |
| grassDetail | TexturedGrass.png | [16,0] | (195,215,89) | 3 |
| grassTuft（原 grassFlowers 改名） | TexturedGrass.png | [32,16] | (178,212,86) | 3 |

`path` 键已删除（它是错的映射，道路改由 `deadGrass` 表达）。现在 13 个 world 键**两两无重复像素来源、也无重复平均色**，并已在 import 脚本里做成**硬断言**，以后同类错误会直接失败而不是静默通过。1167 帧像素比对仍全过。

素材执行者纠正了我一处错误：我给它的 `shore` 格位写错了（`[48,0]` 是纯水面色，`[0,0]` 才是沙色），它按实测改用 `[0,0]`。若不纠正，`shore` 会与 `water` 同色、正好复现要修的 bug。

### 我自己的误判（记录以免重犯）

- 我报告过"战场出现巨大不透明白色矩形，疑似渲染故障"，并**错误地断定那就是水面**。渲染执行者找到真因：`drawRange` / `drawSelection` / `drawViewportHint` 把**像素**当**格**用了——世界坐标下 1 格 = 26 设备像素，但描边宽度又除以了一次 `cell`，于是 `lineWidth` 变成 0.75 世界单位（屏幕上 0.75px），而弧半径是 6 世界单位（156px）。结果填充与深色底衬被放大成约 60px 厚的实心带，三个同心环叠起来就是那块"随帧变化的直角色块"。同类错误共 4 处，现已统一用 `cellPx(px, cell)`。
  **教训**：我看现象时把"平色大块"直接归因给素材，没有先验证绘制层的坐标单位。以后遇到这类问题应先做像素级取证再归因。
- 我也一度以为"选中面板挡住战场中部导致无法放置"是产品缺陷。复核后确认：面板只在选中状态下出现，取消选中或选别处即可解除，这是**既能配置又能放置的正常交互**；是我取证脚本没关面板才放不成部队。不计为缺陷。

### 战斗表现取证（目标要求项）

写了 `tools/combat-evidence.mjs` 在真实战斗里取证。第一次失败，原因是我把防守点放在 y=8~10，而第一波敌人沿 **y=6 走廊**从 x=1 直行——警戒半径够不到，整局 0 次交火。用 `tools/route-probe.ts` 打出真实行军路径后改为贴走廊布防，取证通过：

| 指标 | 结果 |
|---|---|
| 敌人最低血量 | 8 / 62（确实被打伤） |
| 出现受击的帧数 | 12 |
| 同时存活特效峰值 | 3 |
| 击杀数 | 2 |
| 采样帧数 / 页面异常 | 80 / 0 |

截图在 `output/combat/`。

### 视觉修正最终结果（两个执行者均已收工）

- **范围环**：填充 0.12 → 0.03/0.04，色 `#57e0ea` → `#3f9aa6`，描边按半径分档 0.75~1.5 设备像素，只画一圈虚线 + 一圈深色底衬。截图里已是克制的虚线导引。
- **水域**：不再是散点平色块。改为**连通湖泊**（BFS 泛洪 + 距离衰减，上限 3~5 格），实测 2~3 片、共 20~23 格；只有水陆交界用 `shore` 沙岸；走廊 152 格全部改画 `deadGrass` 土黄道路。
- **通路安全（最坏情况证明）**：新增 `Terrain.waterAudit()`，在真实 state 上跑两遍 8 邻域 flood fill——`blockedWater = 0`、`onPlaza = 0`，且**把所有水格都当成障碍时，三个入口仍能到达核心**（`gatesReachCoreWithWaterBlocked = true`）。已作为浏览器验收断言。
- **水面纹理**：素材执行者穷举 `Cliff-Water.png` 全部 5265 个 16×16 窗口，证明**不存在"整格不透明且纯水色"的窗口**，于是按后备方案用 `Shore.png[64,0]`（(66,172,175)，比 `water` 更深）导出 `waterDeep`，由渲染层自动优先采用。**如实说明代价：该格 colors=1 是纯色，只提供明度层次、不提供纹理。** 想要真正带纹理的水需要换素材库（本次未越界引入未核验许可的库）。
- 键名与降级链已清理：`grassFlowers` → `grassTuft`，`path` 全部移除。
