## 成长与共享规则

- `preparation.ts:55` 只对当前净投入对象在开战提交时派发一次培养，随后 endPrep；`prepUses` 以来源 ownedId 和效果序号记录，移动和重复提交不刷新额度，能力成长不递归触发培养。培养及 endPrep 只在合格来源/目标上作用；法术受益按可执行的正基础法术判定，非标签猜测。
- `engine.ts:268` 将 growth 攻/血/法强、培养及装备应用到战斗副本；不会把战斗 buff 写回永久成长。法强成长确实进入 `grants.power`，攻血进入真实攻击、当前/最大生命。
- `engine.ts:341` 只在新回合清空 per-round 效果与 special 预算，进入额外行动轮不刷新；每场 cap 独立保留。
- 核心能力通过 `u.side` 选择同侧/敌侧，以上通用机制双方共用。明确的玩家主将被动、指标统计与蛋进度有 side 0/1 分支，属于所属系统，不是敌方能力缺失。
- 相关现有成长回归：`rework-v011-preparation.test.ts`、`unit-balance-basics.test.ts`、`summon-investment-v012.test.ts`。

## 整局评估时需保留的既有语义

- 熔血巫兽在灼烧结算并减层、死亡结算之后增加剩余灼烧；只有 1 层且该拍烧完的目标不会被重新点燃。因此低层普攻灼烧需要足够持续补层，不能把巫兽当作先加层再跳伤害。
- 法强强化的是施法/蓄力法术；炽棘幼龙、白鬃猎龙、熔甲兽等普攻/被普攻触发叠层不会因培养法强变强。反击也主要吃生存与挨打段数，而非普通攻击或法强培养。
- 满血治疗、满格挡等效果一般按实际有用效果消耗预算；`responseGroup` 组语义则按首个合法目标事件预留整组预算，满状态也会消耗。当前实现已明确注释并有战术回归，策略不可借切换目标重复领组预算。
- 噬焰兽在最后敌人阵亡时不再产兵；这是已有回归明确锁定的终局语义，不应作为强度统计中的漏触发缺陷。

## 新策略独立审查（开发中版本）

审查 `source/scripts/pve-all-builds-v0121-policy.ts` 与 runner，源码仍由 benchmark_sim_impl 完善；以下发现已直接发送给该唯一写入者，未自行修改策略，也不将中途快照当作冻结版验收。

已确认合理的部分：

- 所有招募、买卖、合并、培养、站位、装备和号令使用现有合法 Run API；无直接注入金币、物品或单位。普招与升星奖励均读取当前可见货架，没有战斗预演。
- atk 对溅射/轮换/决斗核，power 对实际 `benefitsFromSpellPower` 单位，反击优先牧师；没有把反击、幼龙普攻叠灼烧或普通攻击误算为法强收益。
- 选阵先加入当前核，故当前核不会被一般评分挤去备战；普通卖出与升星奖励替换保护当前核。自有双单位合并后更新核的 ownedId；Run 合并保留训练、成长与装备，并迁移备战额度与培养日志。
- 决斗与法术按需加入护卫，反击核置队首、牧师置后；法术核心与永夜相邻；炎鬃在队尾溅射核前，实际授予队尾。轮换优先自然轮换体，不假设固定护卫永远有效。
- runner 使用实际伤害种类、引擎决斗计数、治疗和状态事件保留机制证据；每批记录源码哈希并在运行结束核对修改，避免开发中串版作为冻结证据。

已提交的具体风险：

1. 初版决斗站位按原格敌人的 HP/ATK/固有护甲评分，未把紧邻前方嘲讽的实际拦截目标纳入，且未纳入 `EnemyEntry.armor` 覆盖。最小场景是低血格前有高护甲嘲讽：排序认为弱敌易杀，实际普攻命中强护卫；这属于策略误判，会低估决斗路线。需复查最终版是否按实际目标评分。
2. 初版成熟核只检查 train，忽略 growth/equips；审查中读回已扩展为三种真实投入，已修此保留缺口。后续仍需保护“切核后旧训练留备战”的情况，尤其防御后备切真反击：旧墙持有大量 HP，购入低血棘背后立刻把它推到队首，旧墙可能不在阵中。需合法退款/重分配，或合理保留旧前排，不把这种过渡失败归为反击数值弱。
3. 反击 coreIds 包含 `v_wall/l_warden/m_hide` 防御后备；runner 的 `missingCore` 仅检查 firstCore，不能代表反击机制已准入。必须另区分真实 thorns/被普攻反制来源首次上场与实际贡献，缺机制队伍归为 fallback。成长/收益归因同样不能仅用广义 core：灼烧核可能是幼龙，实际法强培养收益来自另一萨满。
4. 任何培养（甚至早期一份 HP）即可长期锁定旧核心，可能导致灼烧路线幼龙早锁、萨满成为副核。这不直接违反合法性，但须按真实上场角色和 burnAdded/burnDamage 判断，不能据固定 core 的直接伤害断言法强培养无效。

买卖成长前提核对：成长来源必须真正上场；卖出事件使用 `sell` 并在移除后按 Run 规则派发，因此不会凭备战席来源获得盟友卖出收益。当前策略有合法卖出，但未保证主动保留并利用所有成长引擎，故“某辅助没有贡献”需要结合是否上场、是否出现合法目标和事件，不可只读购买记录。

## 八路线复查与调参使用边界

已读回新版修复：决斗镜像真实前邻嘲讽拦截，纳入关卡护甲覆盖及星级攻血；成熟核覆盖 train/growth/equips；反击获得真反击/熔甲兽后可合法卖掉持有训练的防御后备并退款，日志明确记录损失的永久成长。runner 新增逐来源真实伤害、buff 和献祭事件，足以在分析时把 fallback 与机制已触发分开。`missingCore` 仍只是广义核心标志，禁止单独当成型指标。

新增 shield：以雄狮置前吸收格挡、培养格挡及血攻，banner/warden/cliff 支援，符合消盾转攻实际机制，未看到把法强当反击或盾成长的错误。

新增 sacrifice 发现需修的实质站位冲突，已同时通知主责与实现者：当 void 为核、阵中另有 ritualist，当前排成 `[void,...,fodder,ritualist]`；void 只吃队尾，最后的 ritualist 不合格，导致 void 自己不献祭。该版本 sacrifice 结果不能据此判断 void 产品强度，需修为优先满足当前核心的祭品位置契约后重跑相关策略。另建议排除含永久成长/装备的成熟祭品，并避免先训练准备献祭的战体，否则策略会损失本来可保留的投入或在下一备战自行取消其祭品资格。

调参适用结论：六个原新增路线及 shield 可作为“这套可见信息启发式合法策略”的开发诊断证据；献祭需修上述冲突后再纳入。任何低胜率都必须先核对缺卡、实际上场、机制触发、投入去向与失败战斗，才可以作为产品调参候选依据。通过单个策略不能证明某路线最优强度或全体玩家难度；尤其冻结旧核、辅助只优先选一名、固定主将指令和弱敌评分仍是启发式，无法代表所有合理组合。若某路线很少获得真实机制来源，证据支持的是可获得性问题，不能直接支持伤害/成长不足。

灼烧归因局限：单来源直接伤害表不包含无来源的灼烧跳伤，需结合全队 burnDamage、每来源叠层事件与触发时序；不要用核心直接伤害占比比较灼烧与纯攻击。反击、盾成长、献祭也应使用本身事件与后续收益，不只看施法次数。

核心冻结后只读核对 `source/src/core/route.ts` 全部 RAW 三章主线、战斗变体、普通/精英分岔与首领阵列，以及 `encounter*.ts`：均未出现本次改卡 `s_lord`、`n_thorn`、`a_void`、`n_ritualist`。`chapter()` 只按 RAW 复制并缩放已有攻血，不会按招募池动态换卡，故这四张卡的增强不会直接提高当前正式路线敌军的能力。
